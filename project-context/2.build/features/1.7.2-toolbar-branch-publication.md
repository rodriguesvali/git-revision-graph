# Contextual toolbar branch publication

## Define

Approved scope: reuse the toolbar Push slot to publish the current local branch when
it has no matching upstream. Preserve normal Push and its force-push menu for a
tracked branch. Match the existing same-name upstream publication policy, including
confirmation before replacing differently named upstream tracking.

Acceptance: Publish sends the existing publish-branch message for current HEAD;
published branches send normal push-current-head; publication hides the force menu;
state updates and repository switches recalculate the action and close stale menus;
busy, detached, empty, and missing-HEAD states cannot submit a primary action.
The context menu remains available for publishing other local branches.

## Build

- `remoteToolbarUi.ts` owns action selection, primary dispatch, tooltip/accessibility
  labels and force-menu visibility. Publish uses a cloud-upload SVG, following the
  Source Control reference; Push restores repo-push. CSS shows exactly one icon
  from the same host-derived action state. The shell supplies both accessible,
  decorative SVGs; toolbar icon CSS lives in `toolbarIconStyles.ts` to keep the
  main stylesheet within its existing size limit.
- `bootstrap.ts` and `interactions.ts` wire the current host state into that adapter.
- Existing host authorization, mutation coordination, remote selection, confirmation,
  conflict checks, Git API and refresh workflows are reused without protocol changes.
- Runtime tests exercise publication, transition to push, different-name upstream,
  repository switching, stale force-menu closure and disabled states.
- README and unreleased changelog describe the behavior. The interactions size
  baseline is reduced following extraction into the existing toolbar module.
