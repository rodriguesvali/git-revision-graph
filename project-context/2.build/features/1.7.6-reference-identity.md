# Reference identity in comparisons and creation

Review item 2: a branch and a tag can share a short name while pointing to
different commits. Comparisons and reference creation must use the selected
kind rather than Git's short-name precedence.

Graph comparison and unified diff messages carry the selected graph commit
hash. The reference picker retains the reference kind, allows namesakes to be
compared, and resolves names in their specific namespace. Branch and tag
creation resolves a typed source to a commit before invoking Git. The resolver
uses an exact reference lookup before peeling tags, so a deleted ref cannot
fall back to a similarly named ref in another namespace. Remote branch tracking
continues to use the original upstream name.

Coverage includes same-named branch, annotated tag and remote, literal names
beginning with `refs/`, missing references and graph message construction.
On 2026-10-28 `npm test` passed 1,224 tests, `npm run test:platform` passed 53,
and `npm run quality:check` passed. The Git fixture also creates a tag from the
selected branch and a branch from the selected annotated tag and checks their
actual commit hashes.
On 2026-10-28, the maintainer reported that the requested manual smoke tests
passed; VS Code version, platform, and individual scenarios were not supplied.
Rollback reverts the identity changes without deleting any user references.
