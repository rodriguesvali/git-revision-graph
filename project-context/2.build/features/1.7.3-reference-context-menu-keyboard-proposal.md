# Reference Context Menu Keyboard Interaction — 1.7.3

Status: Approved and implemented; automated and Chromium verification passed; integrated manual smoke pending
Date: 2026-10-03

## Discovery and Verified Evidence

The maintainer requested another small improvement for 1.7.3, using graphify.
The existing functional improvement makes long reference names fully readable.
Graph queries surfaced review-workflow accessibility and the graph-menu functions
`openContextMenu`, `appendMenuSubmenu`, and `closeContextMenu`. Source inspection
confirmed an opportunity to complete keyboard interaction in that same surface:

- `src/revisionGraph/webview/script/bootstrap.ts:1501`: reference keydown handles
  Enter/Space selection, with no explicit Shift+F10/ContextMenu opening.
- `script/bootstrap.ts:1514`: contextmenu opening uses event coordinates. Browser
  handling of a keyboard-generated contextmenu event has not been reproduced;
  lack of an explicit shortcut handler does not prove the shortcut never works.
- `script/interactions.ts:239`: opening places the menu without managing focus.
- `script/interactions.ts:387`: submenus support entering with Right/Enter/Space
  and returning with Left, but lack Up/Down/Home/End item navigation.
- `script/interactions.ts:593`: closing removes items without restoring focus.
- `src/showLogWebview.ts:1184`: Show Log already handles Shift+F10/ContextMenu
  explicitly and anchors opening to the focused element.
- `test/revisionGraphWebview.test.ts:973` guards against unconditional focusing
  of the first menu item. Preserve mouse behavior rather than removing this guard
  without understanding its intended interaction.

These are source findings, not results of a live keyboard usability test.

## Approved Scope and Acceptance Criteria

The maintainer approved implementation and inclusion in 1.7.3 on 2026-10-03.

Complete keyboard operation of reference context menus within the graph:

1. Shift+F10 and the ContextMenu key open beside the focused reference and focus
   the first appropriate item, preserving Enter/Space reference selection.
2. Up/Down move among items in the current menu; Home/End reach its boundaries.
   Focused items remain visible when long labels require vertical scrolling.
3. Right enters a submenu and Left returns to its trigger. Escape closes the
   current submenu first, then the main menu, returning focus appropriately.
4. Enter activates an enabled action. Disabled actions remain non-activatable;
   menu/menuitem roles and disabled states must agree with keyboard behavior.
5. Tab exits cleanly; keyboard handling stays scoped to the open menu and does
   not capture search-input or unrelated graph controls.
6. Keyboard dismissal restores focus to the invoking reference if still present.
   Pointer clicks and actions opening another dialog must not have their focus
   stolen. Asynchronous remote-tag menu rebuilding must preserve logical focus.

Use the [W3C APG menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)
as the interaction reference. No accessibility conformance claim is implied.
Retain Git action policy, conflict guards, selection rules, and multi-repository
behavior. No dependency, protocol, contribution-point, or architecture change is
proposed.

## Implementation

- Added `runtime/contextMenuKeyboard.ts` as the focused browser interaction owner,
  registered in `tsconfig.webview.json` and the test-runtime export bridge.
- `script/bootstrap.ts` supplies the existing reference lookup, selection and
  action-menu callbacks. Pointer opening records its invoker without forcing focus;
  keyboard opening focuses the first enabled top-level item.
- `script/interactions.ts` supplies menuitem semantics, explicit disabled states
  and stable action keys. Submenu triggers no longer reopen merely because Left
  or Escape restores focus to them; hover and click opening remain available.
- Vertical navigation wraps and skips native disabled buttons, preserving the
  existing disabled-action policy. Tab restores the reference before allowing
  native focus movement. Keyboard activation restores focus before the action
  can open a dialog/editor; subsequent closing does not steal that new focus.
- Remote-tag rebuilds restore the focused action/submenu; disappearing or disabled
  actions fall back to the first enabled top-level item. Detached references can
  restore to a rendered replacement with the same identity; absent ones are safe.
- Reduced file-size baselines: bootstrap 1753 to 1752 lines, interactions 996 to
  994. No complexity baseline was increased. README, changelog, feature index and
  release readiness now include this approved improvement.
- Visual inspection found that the existing menu layer (60) sat below the toolbar
  (70), hiding focused actions in very short panes despite valid menu geometry.
  `webview/styles.ts` now places it at 74, above the toolbar/minimap and below Flow
  dialogs (75) and loading overlays (80). An actual browser hit-test failed before
  the correction; regression checks now include visible stacking, not just bounds.
