# 1.6.3 Show Log Expanded File Spacing

Status: Implemented; automated validation complete; manual smoke pending
Last updated: 2026-08-01
Baseline: `1.6.3` release cycle

## Goal

Keep changed-file rows compact and consistently spaced when a Show Log commit is expanded,
regardless of how many files the commit contains.

## Cause

Continuation SVGs used percentage height inside flex rows whose height was not yet definite. Their
intrinsic SVG height then contributed to grid sizing once per changed file, making the expanded
commit grow disproportionately with the artifact count.

## Scope

- Give each file continuation row a fixed 24 px flex basis matching the file row.
- Give search and status continuation rows fixed 36 px and 34 px bases.
- Set the corresponding continuation SVG heights explicitly so intrinsic SVG sizing cannot expand
  the rows.
- Preserve graph continuity, file filtering, file actions, and collapsed commit density.

## Acceptance Criteria

- Expanded file rows remain separated by 24 px with no proportional blank area.
- Large commits grow linearly by the visible file-row height only.
- Search and status rows stay aligned with their graph continuation segments.
- Collapsing the commit restores the normal compact row.

## Verification

- Assert the fixed flex bases and SVG heights in the rendered Show Log stylesheet.
- Run `npm run quality:check`, `npm run build`, `npm test`, `git diff --check`, and
  `graphify update .`.

## Manual Validation

- Expand commits with few, dozens, and hundreds of changed files in an Extension Development Host.
- Confirm file rows remain compact, the next commit follows immediately after the file list, the
  graph line remains continuous, and filtering does not reintroduce excess vertical space.

## Release-note Impact

Record compact, count-independent expanded file spacing under the `1.6.3` Show Log notes.
