# Flow Governance configuration diagnostics — 1.7.1

Status: implemented; automated verification passed; manual smoke pending
Date: 2026-09-05

## Define

Second maintainer-authorized incremental UX improvement. Show configuration status and the host's
validation details beside Flow Governance in View. Explain missing configuration, disabled activation,
and invalid/unreadable configuration without blocking the graph. Offer Open Configuration for an
existing or invalid configuration; path-setting failures direct the user to the existing configPath
setting. Missing-file recovery explains the existing enable/create actions and never silently creates a file.

Acceptance: messages identify the problem; untrusted diagnostic text is rendered as text; opening uses
only the configured file of the displayed repository, with existing path safety; stale, malformed,
loading and saving requests are rejected. Errors clear when updated state reports a corrected config.

## Build

- Add repository-scoped `open-flow-config` through shared protocol, validation, authorization, handler,
  controller composition and the Flow Governance workflow. The host resolves the file path; no browser
  file path is accepted. Recheck repository/disposal before revealing an asynchronously opened document.
- `flowConfigRecovery.ts` reuses path inspection and opens invalid JSON for repair, without rewriting it.
- `flowConfigUi.ts` renders status and diagnostics in View and binds the action to the displayed repository.
- Enrich unavailable-action warnings with the current resolution and recovery guidance.
- Extract existing form CSS into `flowFormStyles.ts` and lower the stylesheet size baseline; preserve
  current graph geometry, contributions, policies and Git mutations.
