# Show Log Loading Feedback — 1.7.3

Status: Implemented; final release smoke completed by maintainer confirmation
Date: 2026-10-03

## Problem and Decision

The maintainer screenshot shows a header `Loading` chip and a `Loading log...`
content card for the same operation. Graphify pointed to Show Log state/rendering;
source inspection confirmed `buildShowLogEmptyMessage` supplies the loading text
while the webview independently renders the header chip.

Keep one indicator at the stable header location for initial loads and searches.
Use the existing `loadingLabel` when supplied. Keep pagination feedback at the
bottom of the loaded list, where it describes adding commits rather than replacing
the current results. No additional spinner, overlay or skeleton is needed.

## Acceptance and Implementation

Changed production files: `src/showLogWebview.ts` and `src/showLog/webviewStyles.ts`.

- Suppress the content empty-state card while the full log is loading.
- Render the table only when commits exist, avoiding a phantom empty header.
- Keep `Loading more commits...` for pagination; suppress it during full loading
  even if pagination flags overlap. Existing commits remain visible.
- Give the header chip `role="status"` and `aria-atomic="true"` for polite status
  semantics. Existing CSS hides it when loading completes.
- Preserve custom search labels, no-match/ref-empty messages, errors and help.
  Preserve filter input/focus, host protocol, pagination requests, Git operations,
  CSP, dependencies and package metadata.
