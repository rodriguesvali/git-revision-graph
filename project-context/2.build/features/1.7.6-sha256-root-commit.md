# Show Log root commits in SHA-256 repositories

Show Log previously compared every root commit against Git's SHA-1 empty tree,
which fails in a SHA-256 repository. The host now selects the standard empty
tree object ID from the full commit ID's format for root change lists and root
file diffs. Non-root commits continue to use their first parent. Invalid full
object IDs fail explicitly; no Git objects or repository files are written.

Regression coverage uses temporary Git repositories in both object formats,
checks root additions and non-root modifications, verifies the empty-tree IDs
against Git, and exercises the root file-diff action. On 2026-10-28,
`npm test` passed 1,229 tests, `npm run test:platform` passed 53, and
`npm run quality:check` passed. Manual Extension
Development Host checks remain pending for expanding and opening a root file
in both formats. Rollback restores the previous SHA-1-only behavior.
