# 1.6.7 Flow Governance File Toggle

Status: Implemented
Target version: `1.6.7`
Opened: 2026-08-15

## Goal

Keep the `Flow Governance` checkbox visible and make the repository flow file the sole source of
truth for its checked state.

## Behavior

- When the configured repository file does not exist, Flow Governance state is present and disabled.
- When the file exists and is valid, the checkbox reflects its `enabled` boolean.
- Enabling with no file creates the default configuration with `enabled: true` using exclusive,
  path-validated creation, then opens the new file in a non-preview editor for user review.
- Enabling or disabling with an existing file updates its `enabled` property while preserving other
  supported and future fields.
- The former workspace/user `gitRevisionGraph.flowGovernance.enabled` fallback is removed;
  `gitRevisionGraph.flowGovernance.configPath` remains available.
- Invalid configuration remains visible and diagnosed rather than hiding the checkbox.

## Acceptance And Verification

- The View menu always contains `Flow Governance` for a ready repository state.
- Missing configuration renders the checkbox unchecked.
- Activating from the missing state creates the complete default repository file and displays it in
  the editor.
- Existing safe-persistence guards for path escape, symlinks, hard links, replacement races, file
  size, and JSON validity remain covered.
- `npm run build`, `npm test`, `npm run quality:check`, and `git diff --check` pass.

## Rollback

Revert the state-resolution, webview synchronization, persistence, manifest, documentation, and
test changes together. No Marketplace or dependency rollback is required.
