# 1.7.0 Show Log Row Vertical Alignment

Status: Published; automated verification complete, manual smoke evidence not recorded
Last updated: 2026-09-04

## Goal

Vertically center the primary commit text in compact Show Log rows while preserving graph topology,
reference badges, and expanded file details.

## User Workflow

When scanning Show Log, the commit subject, author, and date have balanced space above and below
inside the primary row.

## Scope

- Fix the primary CSS grid track to the calculated main graph height only for collapsed rows.
- Collapse the unused `files` track to zero in collapsed rows and preserve the established intrinsic
  track sizing for expanded content and its graph continuation.
- Remove the unmatched 5 px bottom padding from expanded file lists so their height ends with the
  final fixed continuation segment.
- Preserve the existing symmetric cell padding and compact/reference/expanded height policies.

## Non-goals

- No font, row-density, graph-marker, reference-badge, or expanded-detail redesign.
- No protocol, Git, manifest, dependency, or package-version change.

## Touched Surfaces

- `src/showLog/webviewStyles.ts`
- `test/showLogWebview.test.ts`
- Release documentation

## Acceptance Criteria

- A collapsed commit does not reserve a stretched empty second grid track.
- Primary commit cells occupy the complete calculated main-row height and retain centered alignment.
- Expanded file content and graph continuation retain their established intrinsic grid geometry.
- Expanded file lists and graph continuations terminate at the same vertical coordinate, including
  commits with references.
- Compact, reference-bearing, and expanded graph geometry remains unchanged.

## Risks

- Collapsed-track sizing must remain synchronized with `--show-log-main-graph-height`.
- The first implementation applied explicit tracks to expanded rows and created a graph-line gap;
  regression correction now scopes the rule to collapsed rows only.
- A residual 5 px file-list bottom padding had no matching graph-continuation segment and could
  expose a small line break before the following commit when a referenced row was expanded.

## Test Plan

- Assert the explicit main/automatic detail grid-track contract in generated Show Log CSS.
- Assert that expanded file lists have no unmatched bottom padding.
- Run `npm run build`, focused Show Log tests, `npm test`, `npm run quality:check`,
  `git diff --check`, and `graphify update .`.

## Manual Validation

Open Show Log with compact, reference-bearing, selected, and expanded commits in light and dark themes;
confirm balanced vertical spacing and continuous topology lines.

## Release-note Impact

Show Log commit text is vertically centered within compact rows.

## Handoff Notes

The correction and its expanded-row follow-up passed all 841 tests, the 2 focused Show Log webview
tests, `npm run quality:check` for 255 files and 2,446 functions, `git diff --check`, and `graphify
update .` on 2026-09-04. The follow-up removes the residual 5 px mismatch between the expanded file
list and its graph continuation after manual inspection of a referenced commit exposed a small
terminal line gap. Visual confirmation of the corrected expanded state remains pending.

Rollback is limited to the collapsed grid-track and expanded-list padding CSS declarations, with no
persisted-state or compatibility impact.
