# 1.6.3 Show Log Commit Checkout And Tag

Status: Implemented; automated validation complete; manual validation pending
Last updated: 2026-08-01
Baseline: `1.6.3` release cycle

## Goal

Allow users to check out an exact loaded commit or create a local tag from it directly through the
Show Log commit context menu.

## User Workflow

1. Open Show Log and right-click an individually selected commit.
2. Choose `Checkout to this` to confirm checkout of the exact commit hash, or choose `Create Tag` to
   enter and validate a local tag name for that commit.
3. Receive the existing Git action feedback and graph refresh behavior.

## Scope

- Add `Checkout to this` and `Create Tag` to the single-commit Show Log context menu.
- Add bounded webview messages and route them through the Show Log message boundary.
- Resolve only currently loaded commits into host-owned `commit` reference targets.
- Reuse `checkoutResolvedReference` and `createTagFromResolvedReference`.
- Serialize both actions through `RepositoryMutationCoordinator`.

## Non-goals

- Do not add the actions to multi-commit selection menus, where the target would be ambiguous.
- Do not add public commands, keyboard shortcuts, settings, dependencies, or manifest contributions.
- Do not change checkout semantics: checking out a raw commit may leave Git in detached HEAD state.
- Do not automatically push a newly created tag.

## Touched Surfaces

- Show Log commit context-menu rendering and browser messages.
- Show Log message validation, dispatch, and provider orchestration.
- Shared checkout and tag workflows through a focused commit-action adapter.
- Webview, protocol, workflow, quality-baseline, changelog, feature-index, and release evidence.

## Acceptance Criteria

- The single-commit context menu shows both actions with the requested labels.
- Checkout asks for confirmation and checks out the exact loaded commit hash.
- Create Tag requests a valid, non-duplicate local tag name and creates it at the exact loaded hash.
- Missing or stale commit hashes cause no Git operation.
- Conflicts and unavailable services retain existing blocking feedback.
- Overlapping mutations in the same repository are rejected.

## Risks

- Checkout of a raw commit produces detached HEAD unless another ref points Git into a branch; the
  existing confirmation makes the selected short hash explicit.
- Creating a tag changes repository refs and must trigger a full graph refresh; the reused workflow
  already owns prepared-refresh cancellation and completion.
- Webview commit hashes are untrusted; bounded validation and loaded-state resolution prevent an
  arbitrary revision from reaching Git actions.

## Test Plan

- Assert menu labels and outbound message shapes.
- Validate accepted and oversized message payloads and dispatcher routing.
- Verify exact loaded commit-target resolution, stale-target rejection, unavailable services, and
  same-repository mutation exclusion.
- Retain shared checkout and tag workflow regressions, including exact raw-commit checkout.
- Run `npm run quality:check`, `npm run build`, `npm test`, `git diff --check`, and
  `graphify update .`.

## Manual Validation

- In an Extension Development Host, run `Checkout to this` on a non-HEAD commit, cancel once, then
  confirm and verify the exact commit becomes checked out.
- Repeat with unresolved conflicts and verify the action blocks and reveals Source Control.
- Create a valid tag, verify it appears in the graph, then try a duplicate and invalid name.
- Verify neither action appears for a multi-commit context and no tag is pushed automatically.

Show Log notes.
