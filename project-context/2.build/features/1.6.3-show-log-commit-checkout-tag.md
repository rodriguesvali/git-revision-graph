# 1.6.3 Show Log Commit Checkout And Tag

Status: Implemented; automated and manual validation complete
Manual evidence: passed by maintainer confirmation on 2026-08-01; environment details were not supplied.
Last updated: 2026-08-01
Baseline: `1.6.3` release cycle

## Goal

Allow users to create and check out an editable, suggested local branch from an exact loaded commit,
or create a local tag from it, directly through the Show Log commit context menu.

## User Workflow

1. Open Show Log and right-click an individually selected commit.
2. Choose `Checkout to this` to review or change the suggested local branch name, or choose
   `Create Tag` to enter and validate a local tag name for that commit.
3. Confirm the branch input to create and check out the local branch from the exact commit.
4. Receive the existing Git action feedback and see the new branch or tag on the commit without
   reopening Show Log.

## Scope

- Add `Checkout to this` and `Create Tag` to the single-commit Show Log context menu.
- Add bounded webview messages and route them through the Show Log message boundary.
- Resolve only currently loaded commits into host-owned `commit` reference targets.
- Reuse `createBranchFromResolvedReference` and `createTagFromResolvedReference`.
- Serialize both actions through `RepositoryMutationCoordinator`.
- Reload the current Show Log source after a successful branch or tag mutation while preserving its
  filter, scope, and panel.

## Non-goals

- Do not add the actions to multi-commit selection menus, where the target would be ambiguous.
- Do not add public commands, keyboard shortcuts, settings, dependencies, or manifest contributions.
- Do not perform a direct raw-commit checkout or leave the user in detached HEAD state.
- Do not automatically push a newly created tag.

## Touched Surfaces

- Show Log commit context-menu rendering and browser messages.
- Show Log message validation, dispatch, and provider orchestration.
- Shared branch and tag workflows through a focused commit-action adapter.
- Stale-safe Show Log reference refresh after successful mutations.
- Webview, protocol, workflow, quality-baseline, changelog, feature-index, and release evidence.

## Acceptance Criteria

- The single-commit context menu shows both actions with the requested labels.
- Checkout opens a branch-name input suggested as `commit-<short-hash>` and lets the user edit it.
- Confirming a valid name creates and checks out the local branch from the exact loaded commit hash.
- Create Tag requests a valid, non-duplicate local tag name and creates it at the exact loaded hash.
- The new branch or tag is displayed on its commit immediately after the action completes.
- Missing or stale commit hashes cause no Git operation.
- Conflicts and unavailable services retain existing blocking feedback.
- Overlapping mutations in the same repository are rejected.

## Risks

- Branch names are user-controlled; the reused input and workflow validate the edited name before
  calling Git, while cancellation remains a no-op.
- Creating a tag changes repository refs and must trigger a full graph refresh; the reused workflow
  already owns prepared-refresh cancellation and completion.
- The Show Log refresh is asynchronous; request ownership and source-token checks prevent an older
  result from replacing a newer source or filter operation.
- Webview commit hashes are untrusted; bounded validation and loaded-state resolution prevent an
  arbitrary revision from reaching Git actions.

## Manual Validation

- In an Extension Development Host, run `Checkout to this` on a non-HEAD commit, verify the suggested
  `commit-<short-hash>` name, cancel once, then edit the name and confirm the branch is created and
  checked out at the exact commit.
- Repeat with unresolved conflicts and verify the action blocks and reveals Source Control.
- Create a valid tag, verify it appears in the graph, then try a duplicate and invalid name.
- Verify both the new branch and tag appear immediately on the affected Show Log commit.
- Verify neither action appears for a multi-commit context and no tag is pushed automatically.
