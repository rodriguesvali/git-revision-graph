# Flow Governance: Start Feature From Release

Status: Implemented; automated verification passed; manual validation pending
Target version: `1.6.2`

## Goal

Allow a user to start a new Flow Governance feature branch from a classified release branch.

## Scope

- Show `Start New Feature` in the Flow Governance submenu for a release branch.
- Authorize both the form-preparation and branch-creation messages when the known source branch is classified as `release`.
- Preserve the existing feature-from-main path and every other governed start-source rule.

## Acceptance Criteria

- A release branch exposes `Start New Feature` alongside its existing Flow Governance actions.
- The host accepts feature-start messages with a known release source for both preparation and creation.
- Features from `main` remain allowed; releases, hotfixes, and tasks retain their existing source constraints.
- The existing feature exact-synchronization preflight applies to release sources unchanged.

## Risks And Controls

- The webview is not trusted: extension-host authorization independently checks the known source reference and Flow kind.
- No Git mutation occurs before the existing guarded, synchronization-aware branch-start workflow succeeds.

## Verification

- Passed: `npm run quality:check` (255 files and 2,463 functions), `npm run build`, `npm test` (830 tests), `git diff --check`, and `graphify update .` on 2026-07-30.
- Pending: manual Extension Development Host validation from a release branch, including the existing synchronization preflight and guarded creation flow.

## Release-note Impact

Flow Governance can now start a feature branch from a release branch.
