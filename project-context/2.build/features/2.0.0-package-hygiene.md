# 2.0.0 Package Hygiene

Status: Complete; approved VSIX creation and clean-profile installation remain release gates
Target version: `2.0.0`

## Goal

Prevent stale production output and development-only files from reaching a packaged or published
extension.

## Scope

- Use the VSCE `vscode:prepublish` lifecycle to run the existing clean production build before
  `vsce package` and `vsce publish`.
- Exclude E2E output, TypeScript build configurations, and the repository's Flow Governance
  configuration from the VSIX file list.
- Verify the actual `vsce ls` result contains the extension host and webview runtime entrypoints
  without the excluded development artifacts.
- Keep package creation, clean-profile installation, and Marketplace publication behind their
  existing approval gates.

## Non-goals

- Do not create a VSIX, publish the extension, change its version, or alter runtime behavior.
- Do not remove source-controlled development configuration from the repository.

## Acceptance Criteria

- `package.json` defines `vscode:prepublish` as the clean production build entrypoint.
- All existing package and publish commands inherit that lifecycle through VSCE.
- `out/extension.js` and `out/webview/revisionGraph.js` remain in the package file list.
- `out-e2e/**`, `tsconfig.e2e.json`, `tsconfig.webview*.json`, and
  `.git-revision-graph-flow.json` are absent from the package file list.
- Build, tests, audits, `vsce ls`, and `git diff --check` pass without creating a VSIX.

## External Contract Evidence

- Context7 library `/microsoft/vscode-vsce` and the installed `@vscode/vsce` 3.9.x source confirm
  that both package and publish flows invoke `vscode:prepublish` before collecting files.
- VSCE `ls` applies `.vscodeignore` and reports the same file collection used for packaging.

## Release Impact

This is release-process hardening only. It adds no command, setting, dependency, runtime behavior,
Marketplace claim, or user-owned file mutation.

## Verification

- `npm run vscode:prepublish` passed and rebuilt the production host and webview output.
- `npm test` passed all 789 compiled tests, including the real VSCE file-list regression.
- `npm audit --omit=dev` and `npm audit` both reported zero vulnerabilities after the maintainer's
  dependency-lock update.
- VSCE listed 649 package files, retained `out/extension.js` and
  `out/webview/revisionGraph.js`, and included none of the excluded development-only artifacts.
- `git diff --check` passed.
- No VSIX was created and no Marketplace action was performed.

## Rollback

Revert the lifecycle script, ignore patterns, and package-output assertion together. No user data
or published package is changed by this build slice.
