# Virtual Scene Topology Cache Performance

Status: Implemented; automated and manual validation passed
Manual evidence: passed by maintainer confirmation on 2026-08-01; environment details were not supplied.
Target version: `1.6.3`

## Goal

Reduce graph-wide work during revision-graph scrolling and zooming by preventing virtual viewport
frames from repeating topology construction.

## User Workflow

1. The user opens or focuses a large revision graph.
2. The webview builds the scene topology when the host delivers the new graph state.
3. As the user scrolls or zooms, virtualization replaces only the visible node and edge markup.
4. Selection, relationship highlighting, search, minimap, and routed edges continue to use the
   stable scene topology without rebuilding it for every viewport frame.

## Scope

- Separate graph-wide topology caches from caches of currently rendered DOM elements.
- Build edge lookup, parent adjacency, child adjacency, and HEAD-distance maps once per ready scene
  state.
- Reset topology when the scene becomes empty.
- Refresh only rendered node and edge elements after a virtual-scene DOM commit.
- Remove the duplicate rendered-element cache scan after the initial virtual commit.
- Keep topology construction in the typed primary-path runtime boundary and DOM collection in the
  typed DOM adapter.
- Add runtime regressions proving topology creation is absent from virtual viewport frames.

## Non-goals

- Changing projection, layout, virtual overscan, bucket sizing, node markup, or edge routing.
- Redesigning minimap rendering, search calculation, selection semantics, or relationship paths.
- Adding incremental host-state patches, a worker, a setting, a command, or a dependency.
- Defining a browser wall-clock threshold in the unit suite.

## Acceptance Criteria

- A ready scene creates topology caches once before its first virtual render.
- Virtual scrolling and zooming never invoke graph-wide adjacency or HEAD-distance construction.
- Virtual DOM commits still refresh rendered node and edge element caches before layout and
  highlight synchronization.
- Empty scenes clear both virtual indexes and topology caches.
- HEAD anchoring, minimap marking, routed-edge lookup, ancestor/descendant highlighting, selection,
  and search retain their existing behavior.
- The initial ready render does not perform a second rendered-element cache scan after the virtual
  commit has already refreshed it.

## Risks And Controls

- A stale topology cache could misroute edges or highlights after a state change. Topology creation
  remains inside the ready-state preparation path and is replaced whenever a scene state arrives.
- Clearing only DOM caches could leave old ancestry in an empty state. The empty-scene path resets
  the topology object together with the virtual indexes.
- Moving HEAD ownership could break minimap or centering. Both now read the same typed topology
  object, and the full webview/runtime suite covers those paths.
- The central bootstrap is already a quality hotspot. Typed cache construction and DOM collection
  were extracted to runtime helpers, and its ratcheted baseline decreased from 1,809 to 1,807 lines.

  scroll repeatedly through distant graph regions and confirm the viewport remains responsive.
- Zoom in, zoom out, and reset zoom while preserving the viewport center.
- Select nodes before and after scrolling and confirm ancestor/descendant highlighting is stable.
- Search for nodes outside the initial viewport, navigate results, center HEAD, and verify the
  minimap and routed edges remain correct.
- Exit focus and repeat scrolling on the complete graph.

## Release-Note Impact

Virtual scrolling and zooming no longer rebuild graph-wide topology on every rendered viewport
frame, removing repeated adjacency and HEAD-distance work from large revision graphs.
