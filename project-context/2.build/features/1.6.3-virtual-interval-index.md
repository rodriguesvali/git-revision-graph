# Virtual Interval Index Performance

Status: Implemented; automated verification passed; manual validation pending
Target version: `1.6.3`

## Goal

Prevent long revision-graph edges from being replicated into every intermediate vertical bucket
while retaining correct and efficient viewport candidate selection.

## User Workflow

1. The user opens a large merge-heavy revision graph.
2. The webview builds one interval index for node layouts and another for edges.
3. Each node or edge is assigned to one balanced interval-tree node regardless of its visual span.
4. Scrolling queries only tree branches and centered intervals that can intersect the viewport.
5. Candidate order, final horizontal visibility checks, rendering, selection, and minimap behavior
   remain unchanged.

## Scope

- Replace the vertical bucket map with a typed centered interval tree.
- Normalize and reject invalid bounds at the index boundary.
- Store each valid entry once in the tree, with two local orderings for upper and lower query pruning.
- Preserve original input order and key-based deduplication in query results.
- Use the same interval index for nodes and edges while removing the obsolete bucket-size constant.
- Add a structural regression using an edge that spans 1,200,000 pixels and an intermediate viewport.

## Non-goals

- Changing scene projection, layout, edge routes, overscan, or final horizontal visibility checks.
- Reducing the complete in-memory scene used by search, minimap, selection, and context menus.
- Moving browser rendering to a worker or changing host/webview messages.
- Adding a setting, command, dependency, contribution point, or wall-clock unit-test threshold.

## Acceptance Criteria

- Index storage does not grow with the number of vertical buckets crossed by an edge.
- A long edge is returned when the viewport intersects its beginning, middle, or end.
- Entries completely outside the queried vertical interval are excluded.
- Invalid entry and query bounds are safely ignored.
- Candidate results retain source order and key-based deduplication.
- Empty and ready scene transitions reset and rebuild the typed interval indexes correctly.

## Risks And Controls

- Incorrect interval pruning could omit an edge that crosses the viewport. The tree distinguishes
  queries below, above, and across each center, and the regression queries a long edge far from both
  endpoints.
- Tree traversal could reorder SVG edges. Stored ordinals restore the original input order before
  returning candidates.
- A degenerate tree could move the cost instead of removing it. Centers use median interval
  midpoints, producing balanced recursion for separated intervals; intervals crossing a center are
  stored at that node.
- Two sorted references are retained for entries crossing a center so upper and lower queries can
  stop early. This is constant storage per entry instead of one reference per crossed bucket.
- `bootstrap.ts` decreased from 1,806 to 1,801 lines and its quality baseline was tightened.

## Manual Validation

- Open a large merge-heavy graph containing long merge edges and scroll through regions between the
  connected commits; confirm the crossing edges appear and disappear correctly.
- Scroll rapidly from the top to the middle and bottom of the scene and confirm viewport rendering
  remains responsive.
- Activate and exit `Focus Descendants`, then repeat the long-edge checks.
- Zoom in, zoom out, select both edge endpoints, search, and inspect the minimap to confirm no visual
  or interaction regression.
- Open an empty scene and then a ready scene to confirm index reset and rebuild behavior.

## Release-Note Impact

Long graph edges are no longer copied into every intermediate vertical bucket; a balanced interval
index keeps storage bounded per edge while retaining correct viewport rendering.
