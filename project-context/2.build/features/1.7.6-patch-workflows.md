## Implementation and Safety

`src/patches/` owns bounded binary-safe Git export, private input snapshots, preflight
and injectable export/apply workflows. Native dialogs, editor checks, storage and
`Repository.apply()` live in `workbenchPatchFiles.ts` / `workbenchPatchApply.ts`.
VS Code 1.100.0's API accepts an absolute patch-file path, not patch contents.
The previous discovery's official API/source verification remains applicable.

Compare exports pinned source/target hashes directly. Worktree export uses a private
index initialized from HEAD plus current cached/nonignored paths, including untracked
and ignored-but-staged additions. It never stages the real index. Tracked diffs use
binary payloads, full hashes, fixed prefixes and no external diff/textconv. Git output
and input are capped at 32 MiB; Git export/check calls have 15-second timeouts. Oversized
or incomplete output fails instead of being saved as a truncated patch.

Import snapshots a bounded regular file into a private temporary directory and uses
the same bytes for checks and API application. It rejects empty input, formatted
multi-message series, submodule changes, sparse-checkout application, incompatible
hunks and unsafe Git paths. Sparse worktree export also fails explicitly; endpoint
comparisons remain available without treating absent sparse files as deletions.
The confirmation identifies repository/branch and states that changes remain unstaged.
Native dirty-editor events update graph menu eligibility without changing other
workspace repositories' state. Detached/tag/remote/other-branch and multi-selection
menus do not expose Apply. Host authorization checks the exact displayed HEAD identity.

The shared mutation coordinator protects import across prompts and repository changes.
Workflow and CLI checks revalidate the attached branch, pinned HEAD, clean state and
absence of merge/rebase/am/cherry-pick/revert/bisect sessions. Context/branch/editor
changes after dialogs abort before application. Native API application has no public
cancellation parameter; external process/filesystem races remain possible. Refresh
actual state after application or failure; never reverse/reset automatically.

To preserve size ceilings, review-panel types, Show Log menu rendering, Unified Diff
orchestration and a native panel adapter moved into focused existing boundaries.
Quality baselines were only tightened. No dependency, manifest, version, publication
or persistent session change is included.

### Multi-selected Commit Export

Ctrl/Cmd + click toggles the existing Show Log selection. Format Patch is available
for two commits alongside Compare, and for larger selections alongside Cherry Pick.
Any selected merge disables the action and is also rejected in the host. The protocol
accepts a bounded explicit hash list (up to 1,000); all hashes must still be loaded
in the captured repository/context. Duplicates are removed, and unselected intermediate
commits are never inferred from a range.

Batch names are `0001-<12-character-hash>.patch`, numbered in reverse displayed
history order, independent of click order. This is a presentation order, not a
guarantee of ancestry or applicability: selections can omit dependencies or span
branches. Each file is an independent single-commit mailbox. All payloads are loaded
before writing, bounded to 32 MiB in aggregate. Empty/unexportable commits fail the
whole batch. Exclusive creation prevents overwriting existing files; failures or
context invalidation remove only files created by that request. Cleanup errors are
surfaced; external filesystem changes and process termination cannot be made atomic.
Apply Patch still accepts one file and creates no commits.

### Comparison Patch Filenames

Maintainer-approved UX refinement (2026-10-28): suggestions use readable source and
target labels with pinned short hashes, e.g. `main-03fee33b-to-feature-login-4690b54b-1.patch`.
Commit-only labels are not duplicated; worktree is explicit. Labels are sanitized
and bounded to 40 UTF-8 bytes per endpoint. The existing ordered-endpoint counter,
save/cancel semantics and editable native dialog are preserved. Verification covers
unsafe and long labels, commit labels, direction, worktree and successful saves.
Verification: `npm test` passed 1,214 tests, `npm run quality:check` passed,
and the E2E TypeScript suite compiled. Manual native Save dialog and cross-platform
filename smoke remain pending.

Maintainer refinement on 2026-10-27 replaces the Save Patch suggestion
`comparison.patch` with `from<short-source>to<short-target>compare_<number>.patch`.
The existing shared 8-character hash convention is used; worktree comparisons use
`toworktree` because the workspace is not an immutable commit.

`patches/comparisonNames.ts` prepares a suggestion using the highest matching number
in the default repository folder and the last successful save for that repository
and full ordered endpoint pair. The in-memory counter lasts for the extension
session; after restart, files in the default folder determine the next number.
Cancelled, obsolete or failed exports do not advance it. Successful writes advance
it even when the user edits the filename or saves/moves files elsewhere. Reversing
the comparison or changing repositories/endpoints uses an independent sequence.
The native Save dialog remains editable and handles overwrite decisions in a
different chosen folder. No new persistent data, command or manifest change is added.

The workbench adapter reads directory names and commits the prepared suggestion only
after `workspace.fs.writeFile` succeeds. Ref-to-ref and worktree workflows pass their
pinned direction to this adapter; Show Log Format Patch filenames stay independent.
Focused tests cover existing filenames, gaps, session counters, cancellation/failure
without a successful write, repository/direction isolation, worktree labeling and
invalid revisions. Native smoke exports twice outside the default folder and asserts
that Save dialog suggestions advance from `_1.patch` to `_2.patch`.

Documentation: Context7's rev-list retrieval was insufficient on ordering; the
[official Git manual](https://git-scm.com/docs/git-rev-list) confirms that no-walk
ordering is timestamp/input based. No Git range/walk was added; ordering follows the
captured Show Log display and individual exports reuse the verified `format-patch -1`.

## Delivery and Rollback

### Follow-up Diagnosis: Comparison List Versus File Diff (2026-10-27)

The maintainer reported that after exporting predecessor → main, applying the patch
on a new branch from that predecessor and committing, the new-branch → main compare
still lists the original files while double-clicked diffs appear identical.
Screenshots show the corresponding new-branch and predecessor comparisons.

Root cause confirmed: `refActions/compare.ts` uses `Repository.diffBetween(A, B)` for
the change list. Built-in vscode.git implements that API as `git diff A...B`, from
the merge base to B, in both installed 1.100.0 and 1.143.1 bundles; the
[1.100.0 source](https://github.com/microsoft/vscode/blob/1.100.0/extensions/git/src/git.ts#L1526)
also confirms it. Individual diffs load the two exact revision blobs through
`workbenchDiffPresenter.ts` / `refContentLoader.ts`. Unified Diff and Save Patch use
endpoint `git diff A B`. The original predecessor comparison hides this discrepancy
because its merge base equals the predecessor. Independently committed equal trees
expose it. This is a mismatch of comparison semantics, not evidence of patch failure.

Reproduction used Git 2.55.0, a disposable repository, two modified files, the actual
compiled `loadComparisonPatch`, application on a new branch, and a new commit:
endpoint name-status was empty, triple-dot name-status listed both files, both
individual blobs and the complete trees were identical, and the worktree was clean.
No user repository was mutated. Context7 returned adjacent API material but did not
establish this behavior; pinned official source and installed bundles did.

Recommended fix (not implemented in this diagnosis): use endpoint semantics for
reference comparison change lists, including Show Log comparisons, consistently with
file diffs/Unified Diff/Save Patch. Add equal-tree divergent-history and one-sided
changes regression fixtures. Preserve immutable endpoints, rename paths, root
commits, bounds/cancellation and repository scoping. A merge-base comparison would
need an explicitly named future mode rather than silently differing by surface.
The maintainer subsequently authorized the correction; implementation and final
verification are tracked in [Compare Exact Endpoints](1.7.6-compare-endpoints.md).

Document these actions in README/CHANGELOG and release readiness. No VSIX or
Marketplace command is authorized. Rollback removes protocol/menu/workflow changes
together; it never discards patches, applied files or user commits.
