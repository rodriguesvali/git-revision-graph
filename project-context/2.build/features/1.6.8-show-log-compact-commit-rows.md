# 1.6.8 Show Log Compact Commit Rows

Status: Implemented; automated verification complete; manual smoke pending
Target version: `1.6.8`
Opened: 2026-08-23

## Goal

Increase Show Log commit density by removing file-change statistics from the primary row while
preserving that secondary information in the existing commit tooltip.

## User Workflow

1. The user opens Show Log and scans commits without references as compact single-line rows.
2. Commits with branch, tag, HEAD, remote, or stash references retain their reference-badge line.
3. The user hovers a commit to read its file, insertion, and deletion totals in the tooltip.

## Scope

- Stop rendering the `N files • +X • -Y` statistic in commit rows.
- Create row metadata only for reference badges.
- Let only reference-bearing expanded commits select the taller main graph geometry.
- Use a 26 px main graph height for commits without references while retaining the existing 34 px
  reference height and 42 px expanded-reference height.
- Propagate the selected height through the row, graph stack, main SVG, and centered marker so
  variable-height rows keep continuous topology lines.
- Retain the existing statistics field and tooltip presentation.
- Add focused Show Log webview regressions for row omission and tooltip retention.

## Non-goals

- No change to Git log loading, short-stat parsing, webview state, tooltip content, or expanded file
  details.
- No change to reference badge placement or continuation-row dimensions.
- No command, setting, contribution point, dependency, or package-version change.

## Acceptance Criteria

- Commits without references do not render a second metadata line for file statistics.
- Commits without references use a visibly smaller 26 px row instead of retaining the 30 px CSS
  minimum.
- Reference-bearing commits retain their existing badge line and graph alignment.
- File, insertion, and deletion totals remain available in the commit tooltip.
- Graph segments remain connected and node markers remain centered across compact, reference, and
  expanded rows.
- Expanded commit file details, selection, and hover remain unchanged.

## Risks

- Users who scanned change magnitude directly in the list need to hover for the same information.
- Graph marker and lane alignment require light/dark theme smoke validation for both compact and
  reference-bearing rows.
