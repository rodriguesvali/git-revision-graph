# 1.6.8 Show Log Target Scope

Status: Implemented; automated verification complete; manual smoke pending
Target version: `1.6.8`
Opened: 2026-08-22

## Goal

Ensure that `Show Log`, invoked from a branch reference in the revision graph context menu, opens
the history of that exact branch instead of initially mixing in commits from other branches.

## User Workflow

1. The user opens the context menu on a branch reference in the revision graph.
2. The user selects `Show Log`.
3. Show Log loads the selected branch history with `Show All Branches` disabled.
4. The user may explicitly enable `Show All Branches` to broaden the history.

## Scope

- Initialize target-source Show Log state with `showAllBranches: false`.
- Preserve the exact selected reference as the revision-log target.
- Retain the existing `Show All Branches` toggle and its reload behavior.
- Add orchestration regression coverage for the initial target and explicit opt-in.

## Non-goals

- No protocol, context-menu, graph-selection, Git parser, or range-log changes.
- No command, setting, contribution point, dependency, or persistent preference change.
- No change to Show Log paging, filtering, commit actions, or diff behavior.

## Acceptance Criteria

- Opening Show Log from `feature/demo` loads a target source whose revision and label are both
  `feature/demo`.
- The initial backend load receives `showAllBranches: false`.
- Enabling `Show All Branches` reloads the same source with `showAllBranches: true`.
- Range logs and existing Show Log actions remain unchanged.

## Risks

- Users accustomed to the previous broad default must now opt in to the all-branch view.
- Manual validation must use divergent branches so an accidental broad history is visible.
