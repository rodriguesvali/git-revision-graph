## Scope and Contract

Reject an action from an older repository, graph render, comparison or log source
before resolving its target or invoking its handler. Preserve global bootstrap,
refresh and repository selection, existing Git guards and the published architecture.
S3 cancellation and the broader S4 E2E expansion remain separate work.

Host state supplies `messageOrigin: { repositoryPath, contextId }`; scoped browser
messages echo it as `origin`. Missing, malformed or mismatched origins fail closed.
Payload validators continue producing normalized action intent; dispatchers validate
the outer origin before handing that intent to existing workflows.

- Graph: the dispatcher binds fresh UUIDs to full render results and replacement
  surfaces. Repository changes and disposal retire the current identity. Scoped
  messages must also match the actual current repository. Status/progress patches
  preserve context. Deferred frame sends capture origin before waiting.
- Compare Results: use the existing comparison session, now identified by UUID;
  worktree refresh within that session preserves identity. New comparisons and
  recreated providers/panels get distinct identities. File IDs encode a JSON tuple
  containing repository, path, status and refs, avoiding cross-repository collisions.
- Show Log: UUID source tokens bind all actions, including file search, pagination,
  checkout/tag, clipboard and restore. Filtering/paging retain the source identity.
  The dispatcher invokes the selected handler before yielding, so a microtask cannot
  replace presenter state between origin validation and target capture.
- All surfaces close stale menus when replacing full state. Ready messages remain
  available while empty/hidden; scoped messages without a bound context are rejected.

## Ownership and Review

`webviewMessageOrigin.ts` owns the shared envelope, matcher and inline bridge.
Graph dispatch/lifecycle and the typed runtime own graph binding. Compare review
sessions and Show Log source state own their respective identities. Messaging and
loading script extractions keep renderers within existing quality budgets; the
explicit webview bundle file list includes `script/actionLoading.ts`.

The manual source review checked correctness, readability, architectural boundaries,
input validation and performance. No new dependencies, contribution points, Git
execution paths or persistence were introduced. Token creation and matching add
constant work per state/message. Quality defaults and exceptions were not loosened;
renderer/interaction size and one function-complexity baseline were reduced.
