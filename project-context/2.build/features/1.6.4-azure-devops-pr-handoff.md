# Azure DevOps Pull Request Handoff

Status: Implemented; automated verification passed; manual Azure DevOps Services smoke pending

## Goal

Open the Azure DevOps Services Pull Request creation page with the source and target branch selected
from Flow Governance, and give the user actionable feedback when VS Code cannot launch that page.

## User Workflow

1. A user opens an eligible Flow Governance Promotion PR Context for an Azure DevOps Services remote.
2. The user selects `Open Pull Request`.
3. Existing target and source-publication guards pass, then VS Code opens the Azure DevOps creation
   page with the selected branch names.
4. If VS Code reports that no external application was opened, the user receives an information
   message and can retry or navigate to the repository remote manually.

## Scope

- Build Azure DevOps portal links with short `sourceRef` and `targetRef` branch names.
- Retain URL encoding, Azure DevOps Services remote parsing, origin-first remote resolution, and
  fetch/push repository-identity checks.
- Surface a native non-blocking message when `vscode.env.openExternal` returns `false`.
- Cover the URL contract and the failed browser-launch result deterministically.

## Non-goals

- Azure DevOps REST API creation, provider authentication, Azure DevOps Server support, SSH alias
  discovery, automatic push, force push, or changes to Flow Governance promotion policy.

## Acceptance Criteria

- Current and legacy Azure DevOps Services URLs use encoded short branch names in portal deep links.
- Existing preflight checks complete before browser handoff.
- A `false` result from `vscode.env.openExternal` produces concise user feedback.
- GitHub and other provider URL behavior remains unchanged.

## Risks

- Azure DevOps REST creation uses fully qualified Git refs, but the browser portal uses short branch
  names. Keep those contracts separate.
- Azure DevOps Services portal behavior must still be verified in an Extension Development Host with
  an accessible repository; unit tests cannot authenticate to or render the portal.

## Decisions

- Microsoft Learn's current Azure Repos portal deep-link example uses short `sourceRef` and
  `targetRef` values. Azure DevOps REST uses `refs/heads/*`; this extension is intentionally a
  browser handoff and does not call that API.
- Context7 verified that the VS Code `openExternal` API returns a boolean that indicates whether
  opening succeeded. The project targets VS Code `^1.90.0` and already uses this API.
