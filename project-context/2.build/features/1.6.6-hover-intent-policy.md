# Shared Hover Intent Policy

Status: In progress
Target version: `1.6.6`

## Goal

Replace independent timeout handling in reference tooltips and Flow Governance submenus with one
reusable hover-intent scheduler while preserving each surface's existing delays and keyboard flow.

## Design

- Add a webview-runtime scheduler that can schedule and cancel a delayed action for one target.
- Use separate scheduler instances where a surface has distinct opening and closing delays.
- Keep tooltip opening at 500 ms, tooltip closing at 180 ms, and submenu closing at 120 ms.
- Keep focus transitions immediate and cancel pending mouse-driven closes when focus enters the
  interactive surface.

## Migration order

1. Extract and unit-test the generic scheduler from the existing submenu close scheduler.
2. Migrate submenu close handling without changing its public interaction behavior.
3. Migrate tooltip show/hide timers and add focused regression coverage.

## Risks

- A shared timer must never close a newly entered target after rapid pointer movement.
- Focus movement between a trigger and its interactive surface must cancel pending closure.
