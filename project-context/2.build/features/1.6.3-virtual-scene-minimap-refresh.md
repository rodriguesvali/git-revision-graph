# Virtual Scene Minimap Refresh Performance

Status: Implemented; automated and manual validation passed
Manual evidence: passed by maintainer confirmation on 2026-08-01; environment details were not supplied.
Target version: `1.6.3`

## Goal

Keep virtual viewport commits from regenerating the full revision-graph minimap and from applying
search highlights twice while the user scrolls through a large graph.

## User Workflow

1. The user opens a large revision graph with the minimap visible.
2. Scrolling replaces only the graph elements inside the virtual viewport.
3. The commit refreshes selection, relationship, and search classes on those rendered elements once.
4. The existing lightweight minimap viewport update follows the scroll without regenerating node
   and edge markup for the complete scene.
5. Selection, state, and geometry changes retain their existing full minimap synchronization paths.

## Scope

- Let selection synchronization explicitly skip full minimap rendering for a virtual-scene commit.
- Consolidate selection, relationship, and search highlighting behind one post-commit callback.
- Remove the separate duplicate search-highlight callback from the virtual lifecycle boundary.
- Preserve full minimap synchronization as the default for existing selection and state callers.
- Add regressions that keep full minimap and duplicate search work outside virtual viewport commits.

## Non-goals

- Redesigning or virtualizing minimap content.
- Changing scroll scheduling, zoom geometry, graph projection, layout, overscan, or scene indexes.
- Changing selection, relationship, or search semantics.
- Adding a setting, command, protocol message, dependency, or contribution point.
- Defining a browser wall-clock threshold in the unit suite.

## Acceptance Criteria

- A virtual viewport commit does not invoke full minimap synchronization.
- Selection, relationship, and search highlights are applied once after the rendered-element caches
  and node layout are refreshed.
- Scroll events continue to request the lightweight minimap viewport update.
- Existing selection and state callers retain full minimap synchronization by default.
- Zoom and scene changes continue to refresh minimap content when graph geometry changes.

## Risks And Controls

- Skipping all minimap work could leave the viewport indicator stale. The existing scroll listener
  continues to schedule `syncMinimap('viewport')`; only full SVG content generation is skipped by
  the virtual commit.
- A new scene could initially lack minimap content. Ready-state application retains its existing
  full synchronization after the first render.
- Consolidating callbacks could omit visible-state classes. The post-commit callback still runs
  selection, relationship, and search synchronization together, and lifecycle order is covered by
  the typed runtime test.
- `interactions.ts` remains at its ratcheted 1,021-line quality ceiling. `bootstrap.ts` decreased
  from 1,807 to 1,806 lines and its baseline was tightened accordingly.

  minimap markers remain correct.

## Release-Note Impact

Virtual scrolling now updates rendered highlights without regenerating the full minimap or
reapplying search highlights, reducing repeated graph-wide work in large revision graphs.
