# 1.7.6 Open File

Status: Implemented; automated verification passed; final manual acceptance pending
Date: 2026-10-26
Baseline: `bd98709`, version 1.7.6, VS Code ^1.100.0

## Goal and Authorization

From Compare Results and expanded Show Log files, open the current worktree file
for editing or a labeled historical version for reading. Preserve existing diff,
compare and restore actions. The maintainer authorized implementation with
“pode iniciar a implementação” after the release-opening/build-planning discussion.
Discovery evidence is in [the feasibility analysis](open-file-feasibility.md).
The referenced versioned planning files were absent from the committed baseline;
this record restores their agreed scope and records implementation evidence.

## Scope and Acceptance Criteria

- Open File always opens the current worktree path using the native editor. It
  preserves unsaved content and reports a missing path without creating/restoring
  a file or falling back to a different version.
- Compare Results offers the source/reference historical file and, for two refs,
  the target file. Show Log offers its commit file and a first-parent file for
  deletions. Historical actions identify the revision and read-only behavior.
- Added files have no historical source; deleted files have no historical target.
  Disable absent sides with an explanation. Local availability is independent:
  a historically deleted file may still exist in the current checkout.
- Renames use original and target paths for the corresponding sides. Root commits
  have no parent file. Do not open empty diff placeholders as files.
- Preserve double-click diff, clipboard, Revert policy, multi-repository isolation,
  filters, selections, CSP and keyboard access through the existing context menus.
- Webviews send IDs and a closed set of actions; the host resolves file/repository/
  revision. Reject stale context and wrong commit/change identities before effects.
- Opening changes neither HEAD, index nor worktree bytes. No runtime dependency,
  global command, setting, version bump or new view is part of implementation.

## Architecture and Decisions

- `fileOpen.ts` owns explicit targets, action types and guarded effects. Focused
  `compareResults/fileOpen.ts` and `showLog/fileOpen.ts` select allowed versions.
  Existing panel dispatchers resolve host state and retain origin authorization.
- `workbenchFileOpen.ts` checks local availability (including dirty open documents),
  opens current files through `vscode.open` and historical text through the content
  provider. Recheck context after asynchronous file/document loading.
- Historical snapshot policy: production comparison services resolve named refs to
  commit hashes **before** the Git diff. The completed comparison retains hashes
  and human labels, so branch movement does not change opening/restoration sources.
  Show Log already supplies commit hashes. The resolver remains injectable for
  platform-independent workflow tests; production composition always supplies it.
- `refDocumentUri.ts` shares URI construction with the existing diff presenter.
  Single-file historical editors include a short hash in their display path while
  preserving the actual repository path in the query and the file extension.
- The existing loader retains repository/path checks and I/O bounds. Single-file
  historical reads reject NUL-containing binary content instead of presenting it
  as editable text. Empty text blobs remain valid. General historical binary and
  notebook previews, encoding conversion and later rename following are excluded.
- Dedicated browser menu renderers keep the existing webview file ceilings.
  The allowed size/complexity baselines were reduced where extraction improved them;
  no ceiling was increased and no test or assertion was suppressed.

before replacing its context. This preserves their stale-result/error coverage
with the new asynchronous revision-resolution step; it does not remove assertions.
