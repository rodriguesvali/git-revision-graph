# 1.7.6 Open File at Revision from the Graph

Status: Implemented; automated verification passed; final manual release checks pending
Date: 2026-10-26

## Goal and Scope

The maintainer approved Open File at Revision… on a graph branch, tag or commit.
The action pins the displayed commit, presents a searchable native file picker,
and opens the chosen historical text file read-only with the existing presenter.
List all files in the snapshot, not just its changed paths. Keep existing compare,
Show Log, checkout and graph behavior. No dependency, global command, new view,
checkout, restore, index write, version bump or publication is included.

## Acceptance and Architecture

- Add an Inspect menu action, typed protocol, structural validation, known-commit
  authorization, origin validation and host routing. Derive display labels from
  host state rather than trusting a browser-supplied filename/ref label.
- Read the immutable Git tree on demand with bounded, cancellable CLI execution;
  parse NUL-separated records to preserve spaces, tabs, Unicode and newline paths.
  Omit gitlinks/submodule trees; they are not files in this repository snapshot.
- Search by repository-relative file path. Escape or cancel is a no-op. Do not
  infer the current checkout's paths or follow later renames. An empty tree gives
  an informative empty result. Large-tree limits produce an explicit error rather
  than a silently incomplete list.
- Guard selection against another action, repository change (including A→B→A),
  repository closure and graph disposal. Cancel pending Git/native picker work.
  A branch advancing in the same repository must not change the pinned commit.
- Reuse read-only opening, path containment and historical binary restrictions.
  Test HEAD, index and worktree stay unchanged by listing/selection/opening.

## Build and Verification Plan

2. Guarded picker workflow and native adapter: loading/search/cancel and obsolete
   asynchronous success/failure. Test without native dependencies through injection.
3. Graph protocol/menu/controller integration, origin and routing regressions.
4. Run full build/tests, quality/platform gates, actual minimum/stable Extension
   Host scenarios and structural graph update; update README/changelog/delivery.

## Risks, Delivery and Rollback

Main risks are opening the checkout version, following a moved branch, accepting
stale selections and mishandling unusual paths. Final native keyboard/theme and
Windows acceptance remains separate from deterministic and Linux host evidence.
Record source/platform/host and remaining gaps after verification. Roll back the
new graph action and its workflow/protocol together, preserving the existing
Compare Results/Show Log file opening and user files.

## Implementation and Diagnostic Evidence

- Added the graph inspection menu entry and closed typed host protocol. Message
  validation accepts an immutable hash; state authorization requires it in the
  current scene and the existing dispatcher rejects stale/cross-repository origins.
- `RevisionFilePicker` guards selection with one AbortController per request.
  Native picker hide, newer requests, repository transitions and graph disposal
  cancel loading/selection; late results and failures are discarded.
- The loader runs `git ls-tree -r -z --full-tree <commit> --` with a 15-second,
  16-MiB bound and a 100,000-file cap. Caps fail explicitly, never truncate a list.
  Gitlinks are omitted; empty snapshots have a truthful empty picker. Binary/text
  limitations and final path checks reuse the existing historical presenter.
- Controller/interactions changes remove redundant forwarding functions to stay
  within existing size ceilings. Their ceilings reduced from 742/890 to 739/887;
  no quality bar was raised.
- Initial tree/picker/protocol tests failed before their capabilities existed.
  Regression coverage now includes unusual paths, complete trees across renames,
  malformed/unknown commits, stale origins, Escape, invalid selections and overlap.
- A real minimum-host regression reproduced a valid selection being discarded
  after branch movement. Native acceptance carried the correct file, and no
  cancellation occurred, but object identity changed. Inspection of bundled VS
  Code 1.100 Git source confirmed its repositories getter creates fresh wrappers.
  The guard now compares repository paths, while explicit lifecycle cancellation
  preserves A→B→A safety. The actual native picker/search/pinned-file/cancel/switch
  scenario then passed. Temporary diagnostics were removed.
