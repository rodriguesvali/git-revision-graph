# Tooltip activation delay — 1.7.4

Status: Implemented; automated verification passed
Date: 2026-10-11

The maintainer requested increasing tooltip activation from 500 ms to 1 second
for both Revision Graph references and Show Log commits. This supersedes the
opening delay recorded for 1.6.3 and 1.6.6.

Both existing `TOOLTIP_SHOW_DELAY_MS` constants now use 1,000 ms. The existing
schedulers continue to cancel pending activation on target exit and context-menu
opening. Closing delay and browser-controlled native title tooltips are unchanged.
The two existing webview assertions now expect the requested opening delay.

Acceptance: custom tooltips open after 1,000 ms of continuous hover on either
surface; graph reference focus also uses this delay. Existing cancellation behavior
is retained. Focused Extension Host smoke:
hover briefly, then for over 1 second, and leave/open a menu before activation.

Verification on 2026-10-11: `npm test` passed all 1,039 tests including production
and browser builds, with no failures/skips. Quality checks passed (294 files /
2,786 functions). Both generated runtimes contain the 1,000 ms constant and retain
their existing scheduler use. Graphify AST update and diff whitespace checks
passed. Focused manual Extension Host timing smoke remains pending.
