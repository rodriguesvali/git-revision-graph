# CI Verification Reliability

Status: Implemented; local verification passed; GitHub Actions rerun pending a pushed commit

## Goal

Keep the `1.6.4` verification workflow deterministic and free of known dependency audit findings.

## User Workflow

1. A contributor changes the extension and GitHub Actions runs the verification matrix.
2. The Flow Governance and Pull Request rejected-mutation contract tests wait until their modal
   warning has actually been requested.
3. The test confirms the operation remains pending until that modal is dismissed.
4. Both full and production-only dependency audits complete without findings.

## Scope

- Replace the arbitrary one-event-loop-turn assumption in the two shared-modal-warning contract
  tests with an explicit harness notification.
- Resolve the `js-yaml@4.3.0` development-only audit finding through its compatible
  `4.3.1` lockfile update.

## Non-goals

- Change Flow Governance or Pull Request runtime behavior, repository mutation coordination,
  production dependencies, the extension package, VSIX contents, or Marketplace publication.
