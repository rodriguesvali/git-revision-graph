# Flow Governance dialog keyboard focus — 1.7.1

Status: implemented; automated verification passed; manual smoke pending
Date: 2026-09-05

## Define

Sixth authorized UX increment: keep keyboard navigation within branch/equalization forms. Tab and
Shift+Tab wrap between visible enabled controls; Escape respects the existing processing guard;
closing restores a usable opener or falls back to View. Preserve native typing, selection and submit.
Repository reset must close the old form without moving focus away from the user's current control.
No host protocol, Git behavior, dependencies or release version changes.

## Build

- `runtime/flowDialogFocus.ts` owns initial focus, dynamic tab-stop discovery, wraparound and return
  focus. Hidden ancestors, disabled controls and negative tabindex are excluded. A disconnected or
  hidden opener falls back to the View button. Dialog key events stop before graph shortcuts.
- Branch and equalization controllers share the helper. Initial focus is synchronous after revealing
  the form, eliminating stale scheduled focus after close/reopen. Reset discards return-focus state.
- `flowFormSubmission.ts` accepts a focus callback so processing places focus on the dialog while
  all controls are disabled; Tab stays there and Escape cannot close an in-flight operation.
  Both submit handlers ignore repeated submissions before updating field/AI state, preventing the
  branch handler from re-enabling the AI control during processing.
- Register the helper in main and isolated webview typecheck configurations. Actual dialog tests cover
  focus wrap, structured fields, disabled actions, native Tab/Enter, Escape, return focus, removed
  openers, reset, processing and successful completion.
