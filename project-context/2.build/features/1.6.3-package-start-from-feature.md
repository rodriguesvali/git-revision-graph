# Flow Governance: Start Package From Feature

Status: Implemented; automated verification passed; manual validation pending
Target version: `1.6.3`

## Goal

Let a team consolidate task deliveries in a governed package branch before opening one Pull
Request back to the exact feature from which the package was created.

## User Workflow

1. From a classified feature branch, the user chooses `Flow Governance > Start New Package`.
2. The extension fetches and verifies that the source feature is exactly synchronized with its
   upstream before opening the package form.
3. Package creation uses the configured package pattern, checks local and remote-tracking name
   collisions, creates and checks out the branch, persists the source feature as its promotion
   target, and optionally publishes the package after confirmation.
4. Developers consolidate task deliveries and validate the package branch.
5. The package exposes `Promotion PR Context` for one guarded `package -> feature` Pull Request to
   its persisted source feature.

## Scope

- Add `package` to the governed branch-start protocol and host/browser type boundaries.
- Show `Start New Package` only for references classified as `feature`.
- Independently authorize package preparation and creation only from a known feature reference.
- Apply exact source synchronization before opening the package form.
- Reuse configured package naming, collision detection, description persistence, optional
  publication, mutation coordination, and refresh behavior.
- Persist and load the package's exact source feature as its promotion target.
- Generate exactly one mapped `package -> feature` Pull Request target and expose the existing PR
  handoff from a mapped package.

## Non-goals

- Starting a package from `main`, `release`, another package, or any branch kind other than feature.
- Starting tasks from a package or changing existing task source rules.
- Requiring individual task-to-package Pull Requests or changing generic merge behavior.
- Inferring targets for package branches created before this feature.
- Automatically merging, publishing, force-pushing, or creating provider Pull Requests.
- Adding package-description AI assistance, settings, commands, dependencies, or Marketplace
  actions.

## Acceptance Criteria

- A feature branch exposes `Start New Package`; no other branch kind does.
- Malformed, stale, disabled, unknown-source, and non-feature-source package messages are rejected
  at the extension-host boundary.
- The package form uses the configured package pattern and requires a name and description.
- Source preflight requires the feature and its upstream to be exactly synchronized.
- Package creation records `branch.<package>.git-revision-graph-flow-target=<source-feature>` before
  optional publication; persistence failure prevents publication.
- A mapped package exposes one `Promotion PR Context` target for its source feature.
- An unmapped package or a package mapped to a non-feature exposes no invented PR target.
- Existing governed start-source rules and `package -> feature` transition policy remain unchanged.

## Risks And Controls

- The webview is untrusted; host authorization verifies the current repository state, source name,
  source kind, and enabled Flow Governance state.
- A stale feature base would weaken consolidation; exact-sync preflight fetches and verifies the
  source before the form opens.
- Ambiguous package ancestry could select the wrong feature; persisted local branch metadata is the
  only accepted target source.
- Git mutation remains guarded by the repository mutation coordinator, workspace/conflict checks,
  explicit publication confirmation, and normal non-force push behavior.

## Manual Validation

- From a synchronized feature, create a package, decline publication, and confirm the created branch
  name, checkout, description, and persisted source-feature target.
- Commit consolidated work, invoke `Promotion PR Context`, and verify the only target is the source
  feature.
- Verify behind, ahead, divergent, unpublished, and read-only-remote feature preflight outcomes.
- Verify `Start New Package` is absent from main, release, task, bug, hotfix, sync, package, and
  unknown branches.

## Release-Note Impact

Flow Governance can start a package from a feature, retain that exact feature as its target, and
prepare one guarded package-to-feature Pull Request after consolidated validation.
