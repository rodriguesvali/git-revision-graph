# Focus Descendants Projection Performance

Status: Implemented; automated and manual validation passed
Manual evidence: passed by maintainer confirmation on 2026-08-01; environment details were not supplied.
Target version: `1.6.3`

## Goal

Keep `Focus Descendants` responsive when a user selects a non-root revision in a large,
merge-heavy repository, without changing which commits or projected ancestry paths are shown.

## User Workflow

1. The user invokes `Focus Descendants` on a non-root revision.
2. The graph retains the selected revision and its loaded descendants.
3. Major-operation projection hides intermediate commits according to the existing options while
   connecting visible nodes through the same ancestry paths.
4. The user can inspect, update, or exit the focused graph without the extension host becoming
   unresponsive.

## Scope

- Pass the computed descendant scope into projected-edge resolution.
- Stop hidden-parent traversal as soon as it leaves that scope.
- Replace recursive repeated ancestry walks with an iterative resolver shared by the projection.
- Memoize nearest visible targets for hidden commits while preserving target order, deduplication,
  and `through` path metadata.
- Extend deterministic CI and RC benchmarks with a non-root descendant-focus scenario that hides
  merge commits and exercises projected-edge traversal.
- Add regression coverage for the scope boundary and shared-hidden-ancestry memoization.

## Non-goals

- Changing descendant membership, major-operation visibility, ref filtering, or edge semantics.
- Changing Git history loading, the layout worker, webview rendering, paging, or graph messages.
- Adding a setting, command, contribution point, runtime dependency, or Marketplace action.
- Introducing a fixed wall-clock pass/fail threshold into the unit suite.

## Acceptance Criteria

- Descendant-focused edge resolution never reads parents below the focused anchor.
- Shared hidden ancestry is resolved once and reused by all visible source nodes in one projection.
- Existing visible nodes, edges, and ordered `through` paths remain unchanged.
- The resolver is iterative and does not grow the JavaScript call stack with history depth.
- The deterministic benchmark reports descendant-focus projection and layout measurements for both
  CI and RC tiers and verifies that the non-root anchor remains projected.
- The full test suite and both benchmark tiers complete successfully.

## Risks And Controls

- Stopping traversal too early could remove legitimate focused edges. The same `scopeHashes` used to
  select visible nodes is passed to the edge resolver, and a focused regression verifies the edge
  from a descendant through a hidden commit to the anchor.
- Memoization could change merge-path ordering or `through` metadata. The resolver preserves commit
  parent order and first-target deduplication; the full projection suite validates existing paths.
- A synthetic benchmark could miss the reported shape. The added scenario uses a quarter-history
  non-root anchor, large deterministic tiers, merge commits, hidden intermediates, projection, and
  layout.

## Test Plan And Verification

- `npm run quality:check` passed: 257 files and 2,484 functions checked.
- `npm test` passed: 845 tests, including focused-scope and memoization regressions.
- `npm run benchmark:ci` passed with 1,200 commits: descendant-focus projection 4.06 ms and layout
  92.83 ms for 147 projected nodes and 150 projected edges.
- `npm run benchmark:rc` passed with 12,000 commits: descendant-focus projection 49.89 ms and layout
  195.13 ms for 741 projected nodes and 750 projected edges. Before the correction, the equivalent
  projection did not complete within 10 seconds during diagnosis.
- `graphify update .` and `git diff --check` passed.

## Manual Validation

- In a large merge-heavy repository, invoke `Focus Descendants` on a non-root revision and confirm
  the focused graph opens without freezing the extension host.
- Change the focus anchor and confirm the graph updates responsively with the expected descendants.
- Exit focus and confirm the complete graph returns without reopening the extension.
- Compare representative visible edges and their hidden-commit paths before and after the change.

## Release-Note Impact

`Focus Descendants` remains responsive on non-root revisions in large, merge-heavy histories by
bounding edge projection to the focused scope and reusing shared ancestry results.
