# Flow Governance: Start Feature And Bug From Package

Status: Implemented; automated and Chromium verification passed; Extension Host smoke pending
Target version: `1.7.4`

## Scope And Acceptance

The maintainer requested Feature and Bug creation from a `package` branch.
Treat package as the source of the new branch, using the existing configured
classification (including bare `package`, `package/*`, and custom patterns).

- Offer `Start New Feature` and `Start New Bug` in the package Flow Governance submenu.
- Independently authorize preparation, preview, submission and optional AI text
  assistance in the host for a known reference classified as package.
- Create and check out the configured feature/bug name from the selected package;
  retain description, collision, mutation and optional-publication safeguards.
- Keep feature exact-sync and bug not-behind preflight policies unchanged.
- Reject other start kinds from package, disabled governance, unknown sources
  and stale repository identities.

No new contribution points, configuration, dependencies, automatic merges, PR
integration rules, or publication behavior. This is a creation-source change;
integration transition policy is outside its scope. No external API contract changes.

## Ownership And Verification Plan

- `webview/script/flowGovernanceMenu.ts`: existing menu extracted from interactions,
  with package entries using existing messages. Added to the strict browser bundle.
- `messageAuthorization.ts`: feature/bug source-kind eligibility shared by all forms.
- Tests: host boundary, inherited creation/preflight behavior and rendered menu.
- Gates: build/full tests, quality, graphify AST update, diff whitespace review.
- Runtime: Chromium graph menu and both forms; Extension Host smoke for real
  creation/publication remains a maintainer follow-up.

Before publication, rollback is a scoped revert. Preserve user-owned branches and
Flow configuration. Existing package creation and integration semantics remain intact.
