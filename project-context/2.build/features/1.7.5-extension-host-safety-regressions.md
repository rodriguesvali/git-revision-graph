# 1.7.5 — Extension Host Safety Regressions (S4)

Status: Implemented; automated verification passed. Manual UX acceptance remains separate.
Authorized: 2026-10-17, “pode tratar o achado 4”.

## Scope and Acceptance

Extend the real Extension Host matrix beyond activation and singleton launch.
Use two disposable repositories with identical commits, refs and relative paths.
Exercise actual production panels, host state, webview transport and Git workflows.
Verify stale actions cannot mutate the current repository, fresh actions affect
only the intended repository, failed multi-path restore recovers local files/index,
and closing/reopening during a pending load cannot deliver stale state or errors.

Keep empty/single-repository scenarios and the minimum/stable VS Code CI matrix.
Test instrumentation and controlled UI/fault responses must remain in test/runner
code, with isolated profiles and cleanup. Do not add production test commands,
relax CSP, expose production internals or change dependencies/contribution points.

## Implementation

- The runner adds a default `safety` scenario beside `empty` and `repository`.
  CI's existing minimum/stable jobs automatically execute all three. Fixtures,
  profiles and extension directories are disposable; only their Git data changes.
- `safetyHarness.ts` decorates real panel creation and provides fixture repository
  choices and expected confirmation responses. Commands, presenters, dispatchers,
  mutation coordination and `vscode.git` remain production implementations.
- `webviewBridge.ts` inserts a nonce-bearing test script before product startup,
  preserving CSP and one private `acquireVsCodeApi` instance. Captured stale actions
  traverse real VS Code transport. Compare/Show Log fresh restores originate from
  actual DOM context menus. Host posts, browser acknowledgments and JS errors are
  observed without exposing production internals or adding product test commands.
- `gitSafetyFixture.ts` faults only the extension's configured targeted CLI inside
  the fixture. A rename first deletes one local path, then real Git restores the
  later path before returning an injected error. Assert binary original-path
  recovery, current-path recovery and unchanged index. Pending-load tests hold a
  native log process before closing/reopening the actual graph panel.
- Negative controls temporarily bypass the public origin matcher or recovery
  method inside the disposable host, restoring descriptors in `finally`.

## Coverage and Oracles

| Scenario | Verified effect |
| --- | --- |
| Graph A→B→A | Old/missing origin rejected; fresh checkout affects the intended root. HEAD and reflog prove exactly the expected checkouts, including no transient stale checkout. |
| Compare replacement | Same refs/paths have different item IDs across roots. Replay with the current target ID and old origin is rejected; fresh DOM restore changes only B and preserves both indexes. |
| Log replacement | Identical commits across clones retain separate origins. Stale restore rejected, fresh DOM restore succeeds, A stays dirty and B's index is preserved. |
| Partial rename restore | Actual late CLI failure reaches the presenter; both local paths recover, including binary bytes, and the index is unchanged. |
| Pending close/reopen | Real log starts before disposal. Retired panel gets no late posts/errors; reopened panel has a fresh origin, rejects replay and completes a new refresh. |

## Defects Exposed by Real Integration

1. VS Code 1.90's Git state has no `untrackedChanges`; unconditional `.length`
   failed graph loading. Make the newer field optional and guard its length.
   Focused red/green tests cover clean legacy state, legacy untracked files in
   `workingTreeChanges` (mixed mode), and the newer separate untracked collection.
   This field guard is not a complete emulation of newer Git state capabilities.
2. S2's inline `function postMessage` replaced native `window.postMessage` in
   Compare Results/Show Log. VS Code forwards inbound messages using that native
   property; panels bootstrapped but stopped receiving state/control messages.
   Use a lexical `const postMessage` emitter. A VM regression failed before and
   passed after the fix; real panel DOM restore scenarios then passed.

## Limits and Follow-ups

Native confirmation and repository-picker UI are supplied by fixture-only test
responses. Their visual/keyboard/cancel acceptance remains manual, as do other
platforms and packaged installation. Graph fresh checkout uses real transport
messages; these tests do not exercise every graph DOM emitter or every Git action.
The pending native Git producer honors cancellation; producer noncooperation is
proved separately by S3's controlled-promise regressions.

On 1.90, a same-commit branch checkout left an old observed graph heading while
HEAD/reflog changed. The replay test uses real Git effects and does not claim to
verify automatic heading refresh. A compatibility probe also found that legacy
`git.untrackedChanges: separate` hides untracked changes from this public state
subset. See the [compatibility assessment](../../1.define/vscode-1.100-compatibility-assessment.md)
for the historical observations. The maintainer subsequently approved the
[1.100 minimum](1.7.5-vscode-1.100-baseline.md), retiring support for 1.90–1.99;
this decision does not establish that the heading behavior itself was corrected.

## Handoff and Rollback

New E2E modules: `webviewBridge.ts`, `safetyHarness.ts`, `safetyScenarios.ts`,
`gitSafetyFixture.ts`, `negativeControls.ts`; runner/entry updated. Production

focused Node regressions. Reverting the E2E expansion changes verification only;
keep the two discovered runtime corrections unless reverting their contracts and

the delivery artifacts. No graph/performance algorithm changed.
