# 1.7.5 — Bisect Target Identity

Status: Implemented; automated verification passed.
Approved: 2026-10-17, “Pode seguir com o item 3”.
Scope: B3 from the [bisect review](../bug-bisect-fragility-review-2026-10-17.md).

## Define

Selecting a branch whose name also identifies a tag can prepare a search with
the tag's commit. The graph sends `refKind`, but the host handler drops it before
Git resolves the unqualified name. Preserve the required kind through dispatch,
controller composition and session preparation; resolve named references in their
own namespaces. Show Log must explicitly prepare its loaded commit hash.

Acceptance: colliding branch/tag/remote/stash names resolve the chosen kind;
annotated tags peel to commits; a missing selected ref must fail rather than fall
back to a different namespace. HEAD and commit selection retain their meaning.
Preparation must preserve HEAD, worktree, refs and absence of bisect metadata.
No new protocol fields, dependencies, version changes or release operations.

## External contract

Context7 `/git/htmldocs` confirmed Git revision disambiguation (tags precede
branches, then remotes), explicit namespaces and `^{commit}` peeling. Its current
documentation is advisory; disposable real-Git tests on 2.55 verify local behavior.
Sources: [gitrevisions](https://git-scm.com/docs/gitrevisions) and
[git rev-parse](https://git-scm.com/docs/git-rev-parse). A second focused lookup
confirmed `show-ref --verify --hash` exact-path semantics; see
[git show-ref](https://git-scm.com/docs/git-show-ref).

## Build

The existing required `refKind` now crosses the graph handler, controller and
session boundary. `BisectGit.resolveTarget` qualifies the graph's short names
within heads/remotes/tags/stash, captures the object ID with exact `show-ref`,
then peels that captured object to a commit. This avoids revision-name fallback
even when a disappeared branch has a tag named `refs/heads/<branch>`. Literal
branch names beginning with `refs/` are still short names within heads.

Commit targets require full hashes; HEAD keeps the same-revision guard. The Show
Log controller handoff explicitly supplies `commit`. The selected endpoint is
still pinned once in the existing session, and preparation performs only reads.
No wire fields, saved-session schema, native ownership/recovery, UI, API baseline
or mutation path changed.
