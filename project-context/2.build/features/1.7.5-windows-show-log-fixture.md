# Windows Show Log Search Fixture — 1.7.5

Approved on 2026-10-17 after analysis of the failing GitHub Actions job.

## Cause and Scope

The [Verify run at 62a9807](https://github.com/rodriguesvali/git-revision-graph/actions/runs/39056620037)
failed only in [Windows npm test](https://github.com/rodriguesvali/git-revision-graph/actions/runs/39056620037/job/117465778238):
1,127 passed, one failed, eight skipped. The failing Show Log search fixture
attempted to create `literal-文件\nname.txt` and received ENOENT before querying Git.
The same failure occurred in the previous run at 5f28389. Linux/macOS verification
and both minimum/stable Extension Host jobs passed in the observed run.

[Windows filename rules](https://learn.microsoft.com/pt-br/windows/win32/fileio/naming-a-file)
exclude control characters such as the newline. The existing Linux tests pass.

Acceptance: use a Windows-valid Unicode filename with a space on win32, retaining
the newline path on other platforms. Use the same selected name for creation,
addition/deletion expectations and removal. Preserve all assertions and test cases.

## Implementation and Verification

`test/showLogFileSearchGit.test.ts` selects one platform-specific `literalFileName`.
Runtime search logic, the shared fixture, CI gates and dependencies are unchanged.
Coverage retains Unicode, literal metacharacter contents, added/removed paths,
rename, context-only exclusion, cancellation and invalid revisions.

Verification on Linux: test compilation and both focused Git tests passed;
`npm test` passed all 1,136 tests (zero failures/skips), including production and
webview builds. `git diff --check` and 63 local documentation links passed.
`graphify update .` refreshed structural relationships (6,555 nodes / 13,636 edges);
semantic document extraction was not rerun. Evidence:
`/tmp/windows-show-log-fixture-tests.log` and
`/tmp/windows-show-log-fixture-graphify.log`.

Native Windows confirmation requires a new CI run containing the correction;
local Linux execution cannot establish that result. No tests/assertions were
removed, skipped or relaxed by this change.

No user-visible runtime change or changelog entry is required. Rollback reverts
only this fixture adjustment and restores the known Windows failure. No Git user
repository, package version or Marketplace state is changed.
