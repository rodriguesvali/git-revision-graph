# 1.6.1 AI Request Cancellation

Status: Published in `1.6.1` by maintainer confirmation on 2026-07-29

## Goal

Let users stop an AI request from the same action that started it instead of waiting for generation,
closing a form, changing input, or replacing the active comparison.

## Scope

- Cover the Compare Results AI briefing and the Flow Governance Pull Request title, Pull Request
  description, and supported branch-description actions.
- Replace the sparkle with a square stop icon while the exact request is pending.
- Keep the pending action enabled, expose a cancellation-specific tooltip and accessible label, and
  retain `aria-busy` while cancellation is available.
- Route Compare Results cancellation through its validated webview message boundary and existing
  `CancellationTokenSource`.
- Reuse the existing `cancel-flow-ai-text` request identity, authorization, and host workflow for
  Flow Governance.
- Preserve the previous ready Compare Results briefing when a regeneration is cancelled; an initial
  cancelled generation returns to idle.
- Continue ignoring late results from providers that do not stop immediately after token
  cancellation.

## Non-goals

- No automatic cancellation timeout, provider-specific abort API, background request management,
  model selection change, Git mutation, setting, command, contribution point, dependency, package
  version, VSIX, or Marketplace change.

## Acceptance Criteria

- Every visible in-flight AI action changes from sparkle to stop without becoming disabled.
- Clicking stop cancels only the request identified by that surface and field.
- The action returns to sparkle after cancellation or completion.
- Flow form input, target changes, and dialog close retain their existing implicit cancellation.
- Compare Results restores a previously ready briefing after cancelled regeneration and never
  applies a late cancelled result.
- Tooltip, accessible label, `aria-busy`, disabled availability, and theme-adaptive color states
  remain accurate.
- Webview validation, dispatch, host cancellation, browser presentation, and stale-result behavior
  have deterministic regression coverage.

## Architecture and Decisions

- `src/compareResults/webviewBriefing.ts` owns the local sparkle/stop presentation and emits the
  payload-free `cancelBriefing` intent. Because both glyphs are SVG elements, visibility is changed
  through the reflected `hidden` attribute rather than an `HTMLElement.hidden` property assignment.
- The Compare Results validator and dispatcher route that intent to
  `CompareBriefingController.cancel()`. The controller cancels and disposes its existing token source,
  restores its captured ready/idle state, and retains its request-identity stale guard.
- `src/revisionGraph/webview/runtime/flowAiTextUi.ts` owns the shared Flow sparkle/stop markup. The
  Pull Request and supported branch-form controllers toggle their existing start/cancel methods
  based on the field's pending request ID.
- Flow host protocol, validation, authorization, and workflow cancellation are unchanged because
  `cancel-flow-ai-text` already carries request ID, surface, and field.
- Cancellation is cooperative. The UI and host invalidate ownership immediately; a provider may
  finish internally, but its late result cannot update the active surface.
