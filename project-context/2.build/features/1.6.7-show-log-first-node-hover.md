# 1.6.7 Show Log First Node Hover

Status: Implemented
Target version: `1.6.7`
Opened: 2026-08-15

## Goal

Make the first visible regular commit in Show Log match the familiar Source Control graph cue: an
outlined node at rest that fills with its lane color when the commit row is hovered.

## Scope And Acceptance Criteria

- The first visible non-merge (`outgoing`) node is hollow and visibly larger at rest.
- Hovering the outgoing row fills the node with its existing lane color.
- Other regular commits retain a smaller solid bullet at rest and gain an outer same-color ring on
  hover, increasing their displayed diameter without replacing the bullet.
- Merge commits use the same `11 px` outer diameter as outgoing commits, with a separated `5 px`
  highlighted core that expands slightly beyond the ring on hover.
- The merge ring centers its core through layout alignment rather than border-relative absolute
  coordinates, avoiding subpixel visual offsets.
- The expanded hover core uses symmetric negative inset positioning so it grows equally in every
  direction without participating in grid track sizing.
- The transition continues to use VS Code theme colors.
- The marker keeps equal fixed dimensions independently of variable SVG row scaling.
- Build, Show Log webview tests, the full test suite, quality checks, and diff validation pass.

## Risk And Rollback

The behavior is CSS-only after the first-visible marker is rendered. Revert the Show Log node class,
styles, test assertions, and this artifact together.
