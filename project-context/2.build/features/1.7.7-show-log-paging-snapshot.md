# 1.7.7 Show Log Paging Snapshot

Status: Implemented; automated and Extension Host verification passed

## Scope

The first Show Log page captures immutable target or range commits and, for
all-branches mode, the all-ref tips and anchor offset. Later pages reuse this
host-only snapshot even if refs move or disappear. A new source, scope, filter
or explicit refresh captures a fresh view. Snapshots are checked against the
repository and request to prevent accidental reuse across contexts and are not
sent to the webview. Existing paging and filtered-search limits remain in force.

## Verification and handoff

Real-Git regressions cover branch movement in ordinary, filtered, all-branches
and range histories; branch deletion; explicit recapture; and rejection across
different filters or repositories. An orchestration regression verifies that
the provider forwards the captured identity to subsequent pages and recaptures
on scope changes. `npm test` passed 1,242 tests and `npm run quality:check`
passed. The VS Code 1.100.0 Extension Host safety suite passed on Linux/Xvfb,
including pagination after a branch moves in both branch scopes. Previously
recorded cancellation warnings occurred in unrelated safety scenarios.
Rollback restores re-resolution on every page. Old unreferenced objects may be
removed by external Git garbage collection; a later page then fails visibly.
