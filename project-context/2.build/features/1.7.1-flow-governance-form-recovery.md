# Flow Governance form recovery — 1.7.1

Status: implemented; automated verification passed; manual smoke pending
Date: 2026-09-05

## Define

Third incremental UX improvement authorized by the maintainer: preserve branch-start and equalization
form input after a failed or canceled operation, close only on success, and prevent duplicate submissions.
Acceptance: fields remain visible and disabled while processing; recoverable failures restore editing
and show an inline message; partial creation preserves the draft but disables another submission.
Repository changes reset the dialogs and invalidate their pending responses. Closing via Escape or
backdrop cannot discard an in-flight form. No persistent draft storage is introduced.

Partial completion includes successful branch creation followed by a failed upstream cleanup, description
save, publication, or equalization merge. Existing notifications, confirmations, source-control conflict
handoff and repository mutation leases remain authoritative; no automatic retry or rollback is added.

## Build

- Shared protocol adds a correlated `submit-flow-form` envelope over the existing branch/equalization
  action types and a `flow-form-result` host message. Validation bounds request IDs and input; authorization
  reuses existing action policies and checks repository identity. Valid but rejected requests get a retry
  response through the dispatcher so the UI cannot remain pending after state changes.
- `formWorkflow.ts` composes validated configuration, existing mutation coordination and domain actions,
  reports errors inline, and suppresses completions for another repository or a disposed surface.
- Branch/equalization domain functions report success, retry, or partial outcomes. Publication/description
  failures after local creation are partial rather than silently closing the form or allowing duplicate creation.
- `flowFormSubmission.ts` owns request correlation, pending control state, draft retention, safe retry and
  stale-result invalidation. Both dialog controllers use it; AI work is canceled before branch submission.
- Keep existing standalone message compatibility. Update host guards, factories, trace passthrough, isolated
  dialog typecheck configs, and explicit webview build coverage. Lower the two large script size baselines
  after moving the Flow control synchronization into its existing focused adapter.
