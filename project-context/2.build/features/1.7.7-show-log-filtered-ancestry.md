# 1.7.7 Show Log filtered ancestry

Status: Implemented; automated and Extension Host verification passed.

Filtered results can omit intermediary commits, so drawing actual parent lanes
over the reduced list implies false relationships. While a commit filter is
active, display commit markers without ancestry lines and explain that clearing
the filter restores the graph. Preserve actual parent hashes for commit actions,
merge markers, searches, scopes, truncation warnings and pagination. This is an
explicitly unknown topology, not a projection of hidden merge paths.

The change is contained in the Show Log view-state presentation; no Git query,
webview protocol, repository mutation, or dependency changes are required.
The notice coexists with the existing bounded-search notice. Empty results keep
their existing message. Restoring the former lane behavior reverts the fix.

Jev 1.14 estimated a 0.97 probability that the notice explains both the hidden
connections and how to restore them. This is a supporting assessment of the
wording, not verification of runtime behavior.

Verification: a disposable Git history with a hidden middle commit reproduces
the issue and checks original parent hashes, pagination and restoration; renderer
tests check both merge and ordinary markers and expanded rows. `npm test` passed
1,244 tests and `npm run quality:check` passed. The VS Code 1.100.0
Extension Host safety suite passed on Linux/Xvfb, exercising filter application,
the rendered notice and absence of lines, and restoration in both scopes.
Previously recorded cancellation warnings occurred in unrelated scenarios.
For manual smoke, filter a history containing gaps, inspect the notice and absent
lines, clear the filter, and confirm the graph and file actions return as expected.
