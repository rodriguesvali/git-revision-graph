# 1.6.3 AI Prompt Writing Quality

Status: Implemented; automated and manual validation complete
Manual evidence: passed by maintainer confirmation on 2026-08-01; environment details were not supplied.
Last updated: 2026-08-01
Baseline: `1.6.3` release cycle

## Goal

Guide every extension-authored AI text action toward output that is simple, cohesive, and logically
organized while retaining the existing factual, security, context, and Git-safety guardrails.

## User Workflow

1. Use AI improvement in a Release, Feature, Task, Bug, or Hotfix description; a Pull Request title
   or description; or generate a Compare Results AI Briefing.
2. Receive text that favors familiar words and short sentences, connects related ideas consistently,
   and presents the main point before grouped supporting details.

## Scope

- Define one shared set of writing-quality instructions for simplicity, cohesion, and organization.
- Include the instructions in every Flow branch-description and Pull Request prompt.
- Include the same instructions in the Compare Results AI Briefing prompt.
- Add focused regression coverage at both prompt-composition boundaries.

## Non-goals

- Do not change model selection, prompt roles, context collection, token fitting, output limits, or
  cancellation behavior.
- Do not weaken prompt-injection defenses, evidence requirements, or Git-operation prohibitions.
- Do not add a command, setting, dependency, protocol message, or Marketplace contribution point.

## Touched Surfaces

- Shared AI writing guidance.
- Flow Governance branch and Pull Request prompt composition.
- Compare Results AI Briefing prompt composition.
- Prompt regression tests, changelog, feature index, and release readiness.

## Acceptance Criteria

- Every extension-authored AI prompt explicitly requests simple, direct language.
- Every prompt explicitly requests cohesive text with connected ideas, consistent terminology, and
  no needless repetition.
- Every prompt explicitly requests logical organization with the main point first and related
  details grouped together.
- Existing prompt-specific structure and safety instructions remain present.

## Risks

- Additional instructions consume a small portion of the model token budget; existing prompt
  fitting retains its reserved budget and context-reduction behavior.
- Overly generic quality guidance could conflict with strict output formats; the instructions are
  phrased to complement single-line titles, structured descriptions, and fixed briefing headings.

## Test Plan

- Assert the three shared rules in branch, Pull Request title, each Pull Request description family,
  and AI Briefing prompts.
- Run focused prompt tests, `npm run quality:check`, `npm run build`, `npm test`,
  `git diff --check`, and `graphify update .`.

## Manual Validation

- In an Extension Development Host, invoke one branch-description action, both Pull Request actions,
  and AI Briefing; inspect whether the result is direct, cohesive, and logically ordered without
  losing supplied facts.
- Verify cancel, unavailable-model, and retry behavior remains unchanged.

notes.
