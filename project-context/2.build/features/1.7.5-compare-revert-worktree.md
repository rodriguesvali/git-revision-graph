# 1.7.5 — Compare Results Worktree Revert

Status: Implemented; automated verification passed.
Approved: 2026-10-17, Compare Results functional improvement and screenshot follow-up.

## Define

Show **Revert** for a reference-to-worktree comparison, including a tag, another
branch, remote or commit as source. Hide it for comparisons between references.
Restore the selected source revision's file into the worktree using the existing
executor. Show Log retains its **Revert to this** action.

The reported `v22.3.0-next.2 → Worktree` screenshot while workspace HEAD is `main`
exposed an incorrect interpretation: the previous gate restricted the source to
that attached branch. The corrected condition is the worktree destination; source
identity and attached/detached HEAD do not determine menu eligibility.

Acceptance: the reported tag comparison renders Revert and its actual menu action
restores the source file; reference-to-reference comparisons hide it and the host
rejects forged restore requests. Preserve confirmations, cancellation, native
rename failure recovery, origin/repository checks, mutation coordination and index
protection. No dependencies, versions, contribution points or release operations.

## Build

`canRevertCompareResultItem` in `compareResultsShared.ts` checks the presence of
host-owned `worktreeRef`, which distinguishes worktree items from between-ref
items. It does not inspect HEAD, branch names, labels or commit equality.
`viewState.ts` projects `canRevert`; the single-file client menu uses the flag and
labels the action **Revert**. Multi-selection retains copy-only actions.

`restoreAction.ts` applies the same policy before inspection/confirmation/mutation
and restores from `worktreeRef` on its existing left side. It never falls back to
the left/right ref of a between-ref comparison. Origin, current item lookup,
mutation leases and the safe executor retain ownership of stale context and Git
safety. No new browser message types or repository subscriptions are needed.

Runtime owners: `src/compareResultsShared.ts`, `src/compareResults/viewState.ts`,
`src/compareResults/restoreAction.ts`, `src/compareResultsWebview.ts`. The existing
webview line ceiling tightened from 682 to 681 because the file shrank.

Regression owners: compare shared/view-state/restore/browser tests,
`test/e2e/compareRevertPolicy.ts`, `safetyScenarios.ts` and the test-only webview
bridge. The browser VM now decodes quoted item IDs like a real DOM, allowing it
to exercise actual host-projected JSON IDs. Existing S1 rename recovery scenarios
continue using their original historical source refs.
