# Compare Exact Endpoints — 1.7.6

Status: Implemented; automated verification passed; manual release smoke pending
Date: 2026-10-27

## Scope and Acceptance

The maintainer approved the fix after the
[patch roundtrip diagnosis](1.7.6-patch-workflows.md#follow-up-diagnosis-comparison-list-versus-file-diff-2026-10-27).
Reference/commit comparison lists must describe the two pinned final revisions,
matching individual diffs, Unified Diff and Save Patch. Separately committed equal
trees must report no changes; changes unique to either side must remain visible.
Preserve source → target direction, rename paths, repository/context ownership,
limits, errors and worktree comparison behavior. No new comparison mode, dependency,
command contribution, version bump or publication is included.

## Decision and Implementation

Built-in `Repository.diffBetween(A, B)` uses `git diff A...B`, comparing the merge
base with B. This is verified in both installed VS Code 1.100.0 and 1.143.1 bundles
and the [minimum-version source](https://github.com/microsoft/vscode/blob/1.100.0/extensions/git/src/git.ts#L1526).
Context7 (`/microsoft/vscode`) returned general API access material, not the required
semantics; exact source and local bundles establish the behavior. The public API
available at the minimum does not expose the endpoint change-list operation needed
here, so a bounded read-only Git call is appropriate. The
[minimum public API declaration](https://github.com/microsoft/vscode/blob/1.100.0/extensions/git/src/api/git.d.ts)
also confirms that the internal `diffTrees` operation is not exposed there.

`src/compareResults/endpointChanges.ts` owns explicit endpoint `git diff --name-status
-z`, rename detection and conversion to existing `Change` records. It requires full
immutable hashes (including the existing empty-tree identifier), ends option parsing,
uses explicit revision arguments and a path delimiter, disables external diff/textconv,
limits output to 32 MiB and execution to 15 seconds, and supports abort signals.
NUL parsing preserves spaces/tabs/newlines in paths; incomplete/unsupported records
or paths outside the repository fail rather than creating partial results. Added,
deleted, modified, renamed and type-changed paths retain existing UI status contracts.

Graph/ref actions receive the loader through `RefActionServices`. Show Log commit
comparison uses the same injectable loader by default. Commit expansion also uses it
for parent → commit (empty tree → root), avoiding a merge-base operation on a tree.
Worktree comparisons keep the existing `Repository.diffWith` flow. Git mutations
continue through the built-in API and existing coordinator.

## Verification

- Initial compilation failed for the missing endpoint loader; the focused tests
  subsequently passed (127 including existing ref-action and Show Log regressions).
- Disposable Git 2.55.0 fixtures use the real patch exporter, apply and commit on a
  sibling branch, prove equal trees and nonempty triple-dot output, then require an
  empty endpoint list in both directions. Additional fixtures cover one-sided
  changes, rename paths with tabs, reverse direction, root commits, invalid revisions
  and cancellation. Existing orchestration tests retain explicit loader fakes and
  stale-result/error/pinned-hash checks.
- The first full run exposed a concurrency harness cast as `never` that omitted the
  new injected loader, leaving its old deferred API response unresolved. That worker
  was terminated, the fake was updated explicitly, and all 35 orchestration tests
  passed independently before a clean full rerun. No assertion or gate was weakened.
- Native host regression creates an independently committed equivalent tree in the
  disposable two-repository fixture; it requires the built-in API to reproduce the
  old nonempty list and graph/Show Log to report no endpoint changes. Root expansion,
  unchanged HEAD/index and existing patch workflows are also exercised.
- Initial native attempts required fixture setup corrections: create the test branch
  through the native API and explicitly refresh the graph, then open Show Log on the
  newly created sibling with all branches enabled instead of reusing its earlier
  target's cached history. These waits failed before the corresponding assertions;
  they are not counted as passing native runs.

Final local automated gates:
