# Remote Tag Progress Feedback

Status: Implemented; automated verification complete
Target version: `1.6.9`
Opened: 2026-08-25

## Goal

Make remote tag push and deletion actions show subtle task progress while the remote Git operation
runs, without reloading the graph because the local tag remains present in the loaded graph.

## User Workflow

After confirming a remote tag push or deletion, the graph shows unobtrusive progress feedback while
Git runs. Once Git succeeds or fails, the graph returns to its current state. The
remote-publication badge is updated after success; no graph refresh is scheduled.

## Scope

- Start subtle progress immediately before each confirmed remote tag mutation.
- Clear subtle progress after either a successful or failed mutation.
- Preserve the baseline behavior of not scheduling a graph refresh.

## Non-goals

- Do not change tag selection, confirmation, error, authentication, or remote-picker behavior.
- Do not change branch Push or Pull behavior.
- Do not add commands, settings, dependencies, or Marketplace actions.

## Acceptance Criteria

- Successful remote tag pushes and deletions show and clear subtle task progress without scheduling
  a graph refresh.
- Failed remote tag mutations clear subtle task progress and do not schedule a graph refresh.
- Existing tag-push success messaging and error handling remain intact.

## Risks

- Starting progress before confirmation could show a false task state.
- A failed remote push could leave stale loading state if progress is not cleared.

## Test Plan

- Extend focused tag-push tests for subtle progress and the absence of graph refresh.

## Manual Validation

In an Extension Development Host, push and delete a remote tag. Confirm subtle progress appears
