# 1.7.5 — VS Code 1.100 Minimum

Status: Implemented; automated verification passed.
Authorized: 2026-10-17, “Siga em frente”, following the compatibility recommendation.

## Scope and Acceptance

Raise the supported minimum from VS Code 1.90.0 to 1.100.0. Align the engine range,
exact API type dependency and lockfile, manifest assertions, CI minimum and user
documentation. Keep `getAPI(1)`, the narrow Git adapter and existing defensive
field/event guards. No extension version bump, packaging or publication.

Review the manually maintained adapter against the exact 1.100 contract: remove
the unused unsupported `creatordate` sort alternative. Retain the optional query
convenience because the official runtime supplies a default empty query.

Verify real Git state exposes separate untracked changes and the checkout event,
and the production helper detects the untracked file. Preserve empty/single/multi
repository E2E scenarios. Run full build/tests and the 1.100.0/stable host matrix.
The support decision excludes VS Code 1.90–1.99 from future compatible updates.

## Evidence and Boundaries

The [assessment](../../1.define/vscode-1.100-compatibility-assessment.md) records
the old API gap and scoped runtime evidence. This change standardizes available
capabilities; it does not certify all Git display configurations or resolve the
separate observed graph heading refresh issue by assumption.

Context7 `/websites/code_visualstudio_api` confirmed engine-range installation
policy; exact contracts were verified against the official 1.100 Git declarations.
Sources: [manifest policy](https://code.visualstudio.com/api/working-with-extensions/publishing-extension),
[Git contract](https://github.com/microsoft/vscode/blob/1.100.0/extensions/git/src/api/git.d.ts).

## Implementation

- Engine `^1.100.0`, exact `@types/vscode` `1.100.0`; lockfile diff restricted to
  root engine/type metadata and that type package. No runtime dependency changed.
- CI minimum becomes 1.100.0; stable remains the other entry. Existing package
  output regression derives the expected matrix from the manifest engine.
- `test/e2e/gitApiBaseline.ts` checks real API fields, production dirty detection
  in mixed/separate modes, an untouched second repository and two actual checkout
  events. It creates a unique file in the fixture and restores the isolated
  profile's configuration, branch and subscription in cleanup.
- The probe runs before opening panels, keeping API evidence independent from
  graph heading presentation. S4 then exercises all existing panel/Git scenarios.
- Existing optional-state and optional-event regressions remain defensive tests;
  their presence does not declare older VS Code hosts supported.

## Delivery and Rollback

README, CONTRIBUTING, CHANGELOG, CI, PRD/SAD and release readiness now state the
approved floor. Historical version-specific evidence is retained and marked as
historical where needed. The support decision is resolved; manual prompt UX,
other operating systems and packaged installation retain their separate gates.
No graph heading fix or broad hidden/ignored/submodule policy certification is
claimed. Existing safety guard regressions remain intact.

No package, extension version bump or publication was performed for this
change. Before publication, revert engine/types/lockfile, CI, tests and docs
together if required. Restoring 1.90 support would require reassessing its known
separate-untracked gap rather than simply declaring that older floor supported.
