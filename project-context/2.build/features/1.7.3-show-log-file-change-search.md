## Contract

- One optional `file:` and one optional `change:` filter; combine with AND and
  the remaining literal metadata phrase. Values containing spaces use double quotes.
- `file:` is a literal repository-relative file or directory path, case-sensitive;
  no wildcards/pathspec magic, absolute paths or traversal outside the repository.
- `change:` is literal, case-sensitive text in added/removed text lines, using
  escaped Git pickaxe `-G`. Unchanged context and message-only matches are excluded.
  When combined, the changed line must be in the selected path.
- Duplicate, empty and unclosed quoted filters produce actionable errors.
  Unsupported operators remain ordinary metadata text.
- Preserve source/range/all-branches scope, metadata matching, result order, paging,
  2,000 original-commit scan cap, cancellation and stale-result guards.
- Scan metadata in the existing 200-commit batches; check advanced filters only
  against those explicit hashes with `--no-walk=unsorted`, `-m --first-parent`,
  literal pathspecs and escaped `-G`. No per-commit Git process or unbounded traversal.
  `--diff-filter=ACDMRTUXB` requires a changed path even with explicit hashes;
  `--root` includes initial file creation despite local `log.showRoot` settings.
- Disable external diff/textconv for the native query. Git calls retain timeout and
  output limits and use argument arrays. No repository mutation.
- Discoverable input help, clear error/no-match feedback, and complete commit
  details/actions are required. No new webview message contract.

Sources: inspected Show Log backend and graphify; official Git log/glossary docs
and Context7. Git 2.25 docs describe `--no-walk`, `-m --first-parent` and pickaxe;
local Git 2.55 probe confirmed root/topic/merge matches without duplicate traversal.
Git 2.25 runtime compatibility is not established by documentation alone.
See [Git log 2.25 diff-filter/pickaxe documentation](https://git-scm.com/docs/git-log/2.25.0).

## Implementation

- `source/revisionLogQuery.ts` owns parsing, value validation and native arguments.
- `backendServices/revisionLogSearch.ts` intersects native matches with the original
  metadata candidates. The existing backend owns scanning, source scope and paging.
- The original commit metadata/statistics remain complete; path filtering does not
  narrow expanded commit actions or details. Paths do not follow earlier renamed names.
- Native checks return hashes only (1 MB output, 15-second timeout per invocation),
  at most one additional process per 200-commit batch. Metadata-only searches skip
  this process; metadata phrases remove candidates before native checks.
- Show Log input exposes examples through placeholder/title. Invalid query errors
  suppress the accompanying no-match message. Existing protocol, debouncing,
  cancellation, source ownership and stale-response checks remain in use.
- No dependencies, contribution points, persisted schema or version changes.

Deterministic Git fixtures exposed the explicit-hash/path filtering behavior; an
all-status diff filter fixed it and the same tests passed. Empty/binary files are
covered, so file-only filtering does not depend on text-line matches.
