## Build

- Add an optional typed summary to the existing preview response: name, context, effects, validation
  state/message and details. The host constructs it from the existing name/collision results; retain
  plain-text fallback for unavailable configuration/authorization responses. Browser guards reject
  malformed summary fields and unknown validation states.
- `runtime/flowPreviewSummary.ts` renders safe text in separate fields. The name uses a monospaced
  two-line region; context and effects remain visible. Fixed text regions prevent typing-driven
  resizing. The default summary has no internal scrollbar. Long text can be read in full via
  “Validation details and full name”, with aria-expanded/controls and a focusable scrolling region.
- Only validation is a live status region. Incomplete names receive neutral guidance, updated input
  clears the previous validation to Checking, and conflicts use theme error color plus explanatory
  text. A successful check says only “No conflicts in known branches”; permissions are not guaranteed.
- Details preserve explicit expansion during updates and reset on reopening. The disclosure is a
  normal button within the existing focus trap and is disabled during submission. No-origin
  equalization keeps the structured shell instead of replacing its DOM.
- Register the browser module in main and isolated build configurations. Cover structured payloads,
  guard rejection, safe long-name disclosure, independent live validation, updates, incomplete input,
  equalization direction, and keyboard traversal including the disclosure.
