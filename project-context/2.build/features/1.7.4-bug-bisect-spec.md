# Guided Bug Bisect — 1.7.4

Status: Implemented; automated and Chromium verification passed; focused Extension Host smoke pending
Date: 2026-10-09

## Objective and assumptions

Find the first commit introducing a reproducible bug through manual testing and
Git's native binary search. Start from any commit-resolving graph reference or
any single Show Log commit, using the selected repository's current HEAD as the
other endpoint. This is one capability: a guided, safely recoverable bisect session.

Approved cleanliness scope and flow defaults:

- The selected revision is known to have **no bug**; HEAD is known to have the
  **bug**. Confirm these roles before starting; allow exchanging them.
- “Clean workspace” means the chosen repository has no staged, unstaged,
  untracked or conflicted files, and no unsaved editor documents within it.
  Other repositories in the workspace do not block this repository's session.
  The maintainer confirmed this repository-only scope on 2026-10-09:
  “sim, somente do repositório onde a busca será executada.”
- Testing is manual. The extension does not run user test commands automatically.
- Controls live in the existing graph editor, using its themed dialog patterns.
  A Show Log entry opens/reveals that graph for the same repository and target.

## Entry and initial confirmation

Add **Find Bug Against HEAD…** to graph reference context menus and single-commit
Show Log menus. The host resolves the reference to a commit, pins both full
hashes, and retains the original branch attachment or detached HEAD.

The initial dialog shows repository, selected endpoint and HEAD, commit subjects,
and the roles “Bug absent” / “Bug present”. A **Swap roles** control changes the
roles without changing the two endpoints. Explain that starting temporarily
checks out test revisions and finishing returns to the original branch/revision.

Validate fresh host state on submission. An identical endpoint, unresolved ref,
unborn HEAD, dirty repository, ongoing merge/rebase/cherry-pick, or an existing
external bisect blocks starting with an actionable explanation. No checkout or
bisect metadata is created by merely opening or cancelling this dialog.

Use the complete Git history rather than the loaded graph window or Show Log
page. Branches, remote-tracking refs, tags, stash commits and detached commit
targets share commit resolution; a ref with no valid commit gets an explanation.
For divergent histories, support Git's merge-base checkpoint explicitly: explain
why an additional base must be tested. A bad base means the bug predates the
chosen interval; an untestable base or unrelated history cannot produce a false
culprit. Report the limitation and offer ending/restoring the session.

## Step dialog and wireframe

Example product copy, in the extension's existing English UI:

```text
Find Bug                                        [Hide]
Repository: example-app
Bug absent: v1.6.0 · 41ad0c2
Bug present: HEAD at start · 8bb4d31

Step 3 · approximately 2 tests remaining
TEST THIS COMMIT
7ce24a9  Handle empty query results

Run your usual reproduction or tests in the editor/terminal.
Then choose the result for this revision.

[Bug absent]  [Bug present]  [Cannot test]

[Show commit]  [Undo last answer]
▸ Answers (2)

Return destination: main · 8bb4d31
[Stop and return to main…]
```

- Each response classifies the displayed, host-validated test hash and advances
  to the next checkout. Disable duplicate submissions while a step is processing.
  Display operation-specific progress and announce the new revision when ready.
- **Cannot test** records a skip, not a good or bad result. Give a brief hint for
  revisions that cannot build or reproduce the test.
- **Undo last answer** removes the last recorded answer and reconstructs the
  session from its pinned endpoints and owned history; return to that test commit.
  Require a clean worktree before undoing. Disable before the first answer.
- Expandable history lists each tested commit, subject and explicit answer.
  Show full hashes on request and preserve history when controls are hidden.
- **Hide**, Escape and the dialog close affordance only hide controls. A compact
  graph banner shows “Bug search active · testing 7ce24a9” and **Resume** / **Stop**.
  Leaving the graph for an editor, terminal or Show Log does not end the session.
- Avoid a fabricated percentage. Show step count and Git's remaining-test
  estimate only when available; distinguish the estimate from a guarantee.
- **Show commit** opens Show Log on the current test revision without clearing
  the search. Read-only inspection remains available during testing.

The dialog uses existing VS Code theme tokens, a bounded responsive width,
scrollable content and stacked actions in narrow panes. Labels and text accompany
status colors. Use dialog semantics, an accessible title, scoped focus management,
visible focus rings and live status announcements. Initial focus goes to explanatory
content or a neutral control; Enter must never implicitly classify a commit.
Return focus to the invoking control on hiding when it still exists.

## Dirty-state, completion and recovery UX

If testing creates changes, keep the current revision and answers intact. Show
“Resolve changes before switching revisions”, with **Open Source Control** and
**Check again**. Do not stash, discard, clean or force checkout automatically.
This applies to start, advance, undo, stop and final restoration.

The result dialog distinguishes:

| State | Content and actions |
| --- | --- |
| First bad commit found | Hash, subject, **Show commit**, **Copy hash**, **Finish and return to main**. |
| Inconclusive after skips | Explain why; list the possible culprit commits with inspection actions; offer finish/return. |
| Bug already present at a divergent merge base | Explain that the chosen endpoints do not bound the introduction; offer finish/return. |
| Operation failed | Preserve known session state and current revision; show the error and safe retry/recovery actions. |

Stopping is deliberate: confirm **Stop search and return to main** versus
**Continue testing**. Completion and cancellation restore the original branch
attachment or original detached hash, without moving a branch ref. If the original
branch has moved externally, explain the mismatch before selecting a recovery
destination; do not silently attach to a different revision.

Persist owned-session identity, original destination, endpoints and answer history
per repository/worktree for window reload recovery. On reload, offer resume or
stop/restore after verifying actual Git metadata and HEAD; activation performs no
automatic checkout. Closing the repository or graph preserves recoverable state.
Detect external checkout/reset/bisect changes and pause; never overwrite an
external session or assume stale metadata is still owned.

## Architecture constraints and source ownership

Keep a host-side session owner independent of graph visibility, with thin graph
and Show Log entry adapters. The host is authoritative for hashes, repository
identity, cleanliness, session generation and the current test revision. Validate
webview messages against all of these; reject stale or cross-repository responses.

The built-in `vscode.git` subset in `src/git.ts` has checkout but no bisect API.
Use targeted Git CLI for bisect metadata and native history selection, and prefer
`Repository.checkout` for actual checkouts. A candidate mechanism is native
`git bisect start --no-checkout <badHash> <goodHash> --`, reading `BISECT_HEAD`
and performing guarded API checkouts. Validate start, skip, reset and replay
semantics in disposable repositories before adopting that mechanism. Do not rely
on recently added Git options without confirming supported Git compatibility.

Use `RepositoryMutationCoordinator` for each state-changing step, with fresh
checks around awaited operations; do not hold its lease while the user tests.
Block incompatible extension mutations during an active session across graph,
Show Log and Compare Results. Keep read-only operations usable. Account for linked
worktrees and repository switching; one owned session per affected worktree.

Relevant existing boundaries:

- `src/extension.ts`: shared service ownership and injection.
- `src/repositoryMutationCoordinator.ts`, `src/git.ts`, Git execution helpers:
  guarded mutations, minimal built-in API and cancellable/bounded CLI execution.
- `src/revisionGraph/messageValidation.ts`, authorization/dispatcher/handler and
  `protocol.d.ts`: typed, repository-scoped graph transport.
- `src/revisionGraph/webview/runtime/`: focused dialog/state/render modules,
  following existing Flow dialog and focus patterns.
- `src/showLog/`, `src/showLogView.ts`, `src/showLogWebview.ts`: commit action and
  transport adapters, preserving current filtering and expansion state.
- `test/`: host, Git-fixture and webview regressions; `project-context/` for
  feature and release evidence. Align README and changelog on implementation.

Retain TypeScript modules, explicit unions, injected testable collaborators and
existing formatting. Real example of the existing guarded integration style
from `src/showLog/commitRefActions.ts`:

```typescript

  createMutationGuardedRepository(repository, lease),
  createMutationGuardedRefActionServices(services, lease)

```

No dependency, settings, new editor view or version change is proposed.

## Acceptance and verification

1. Both entrypoints launch the same flow with the correct repository, selected
   hash and HEAD captured before checkout, including refs absent from loaded pages.
2. Dirty/conflicted repositories and unsaved files prevent all revision switches;
   failed guards leave files, refs and answer history intact.
3. Real disposable histories identify the first bad commit for linear and merged
   histories; reversed endpoint roles and merge-base checkpoints have explicit
   outcomes. No recent-page/graph-window truncation affects the search.

## Implementation

`src/bugBisect/` owns bounded native selection, cleanliness checks, session recovery,
pending-answer journaling, input validation and log ownership. The engine uses
`--no-checkout`; guarded built-in Git checkout applies test revisions. Endpoints
and original attached/detached destinations are pinned. Undo reconstructs only
validated recorded answers, without executing replay scripts. Skips can return
several candidates; divergent histories get an explained common-base checkpoint.

The shared mutation coordinator reserves the repository between user tests, using
short operation leases. Fresh guards run before checkout and before metadata reset,
including after restoration. Stored sessions cannot initiate checkout on activation.
Interrupted checkout/restore and failed persistence retain recovery information.

Graph references and loaded Show Log commits share the controller entrypoint.
Show Log captures its source token when opening the menu; stale sources cannot
hand a common hash to another repository. Handoff selects the known repository
before opening the graph. Decisions bind repository, session id and question version.

The existing graph surface renders the dialog, neutral initial focus, stable live
announcements, history, undo, dirty-state recovery and a resume banner. Stop is
secondary during testing; finish is primary after a result. Copy/Show commit use
host-known revisions. The themed controls fit short and narrow panes.

An explicitly confirmed **Detach controls (keep Git state)…** recovery action
releases only extension ownership when an error prevents normal completion. It
does not reset Git or change checkout. Its confirmation displays the original
hash and explains that restoration becomes manual. Normal finish/stop restores
the original revision; an external session is never reset to free the controls.

Extracted fetch-host composition and configured graph limits from the controller
to preserve its size budget. Four file-size baselines and the Show Log validator
complexity baseline decreased; no limit increased. Dependencies, contribution
points, VS Code engine and package version remain unchanged.
