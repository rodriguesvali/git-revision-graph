# Flow Governance: Release-Origin Package And Task Pull Requests

Status: Implemented; automated verification complete
Target version: `1.6.5`

## Goal

Complete the governed Pull Request lifecycle for package and task branches started from a release.

## Scope

- Model `package -> release` and `task -> release` as governed transitions.
- Resolve the persisted source release as the only mapped PR target for release-origin package and
  task branches.
- Require remote target synchronization for every package promotion, matching other governed
  non-production promotions.
- Preserve feature-origin package/task behavior, fail-closed authorization, source publication,
  target readiness, and conservative provider handoff.

## Non-goals

- Provider API integration or automatic Pull Request creation.
- Changing branch naming, branch-start origins, automatic publication, merging, or force pushes.

## Acceptance Criteria

- Package and task branches mapped to a release expose exactly that release as a governed PR target.
- Their PR context, URL opening, and AI text authorization recognize the new transitions.
- Local and remote target divergence blocks package, task, and other guarded handoffs consistently.
- Existing feature-targeted package and task PR flows remain available.

## Manual Validation

- Create package and task branches from a synchronized release, add commits, and verify each opens
  PR context only for its persisted release after local/remote target synchronization succeeds.
- Repeat with a behind, ahead, and divergent target release; each case must block without mutating
  the target.

## Release-Note Impact

Release-origin package and task branches can now complete their governed Pull Request handoff back
to the exact release from which they started.
