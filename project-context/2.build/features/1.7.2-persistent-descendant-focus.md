# Persistent Focus Descendants

## Define

Remember the chosen descendant anchor per repository in the current workspace.
Restore it when reopening the graph, reloading the window, or returning to a
repository. Store the selected commit hash and display label, not a moving branch
reference. Explicit Clear, changing scope, or selecting Focus Range removes the
saved focus, following existing projection behavior. Other projection preferences
and graph limits are unchanged. If an anchor is outside loaded history, preserve
the existing empty focused view and visible Clear control rather than silently
choosing a different anchor.

Acceptance: restoration is applied on the first repository load; repositories and
worktrees do not share focus; clearing survives restart; malformed persisted data
is ignored; delayed/failed writes do not replace newer in-memory choices or block
the graph. Git state must not change.

## Build

`RevisionGraphDescendantFocusPersistence` stores versioned, repository-path-keyed
values in `ExtensionContext.workspaceState`, with existing projection validation,
serialized writes and a session cache. The controller restores initial and changed
repositories and saves projection updates. Activation passes the workspace store
through the editor panel. No new command, message, dependency or setting.

API evidence: Context7 `/websites/code_visualstudio_api`, VS Code API Memento
reference (https://code.visualstudio.com/api/references/vscode-api#Memento), verified
against installed `@types/vscode` 1.90.0: JSON-serializable get/update; undefined
removes a key. Workspace state is preferred over external files.

Tests cover new-session restoration, independent repositories, explicit removal,
malformed values, pending writes and storage failures. A controller integration
test covers first render, repository switching, clearing and controller recreation.
