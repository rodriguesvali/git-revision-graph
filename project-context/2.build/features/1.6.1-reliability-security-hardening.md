# 1.6.1 Reliability and Security Hardening

Status: Planned
Target version: `1.6.1`
Opened: 2026-07-28

## Goal

Correct the highest-value fragilities identified after the `1.6.0` release so repository-controlled
input, asynchronous refreshes, large worktrees and histories, and timed-out Git commands fail safely
without misleading or freezing the user.

## User Workflow

1. The user opens a repository, Revision Graph, Compare Results, or Show Log as usual.
2. Repository-controlled configuration and large Git data sets stay within explicit resource bounds.
3. Newer user actions retain ownership of the visible result when older asynchronous work completes.
4. Limits, failures, and timeouts are reported truthfully and leave the extension responsive.

## Scope

### Priority 0

- Bound Flow Governance config file size, JSON structure, string and collection sizes, and accepted
  regex complexity before runtime classification in `src/revisionGraph/flow/`.
- Prevent stale Compare Results preparation or refresh work from replacing a newer comparison,
  including when the active repository changes.

### Priority 1

- Revalidate repository config path identity at the final persistence boundary and reject symlink or
  path-substitution races without writing outside the intended repository file.
- Replace one-process-per-untracked-file unified-diff behavior with bounded aggregate work while
  preserving path safety, deterministic output, cancellation, and useful errors.
- Surface the Show Log filter scan ceiling and provide an honest continuation or truncation state
  instead of silently treating the first 2,000 commits as the complete history.

### Priority 2

- Escalate Unix Git process-group termination after a bounded grace period when `SIGTERM` does not
  stop a timed-out command.

## Non-goals

- Add new product features, commands, settings, views, menus, or runtime dependencies.
- Redesign Flow Governance, Compare Results, Show Log, or the Git execution architecture.
- Change Git state as part of defensive validation or diagnostics.
- Package, publish, or alter Marketplace state while implementing the corrections.

## Acceptance Criteria

- Repository configuration exceeding documented bounds is rejected with an actionable diagnostic
  before unbounded parsing, allocation, or regex execution.
- Flow regex validation and runtime matching cannot monopolize the extension host with known
  pathological input; safe existing configurations retain their behavior.
- A config write cannot follow a symlink or replacement path outside the intended repository target,
  including a substitution occurring between validation and persistence.
- Only the latest Compare Results request for the owning repository may update its panel.
- Unified-diff generation uses bounded process and output resources for large untracked-file sets and
  preserves unusual-path handling.
- Show Log communicates when search was truncated and does not claim that an older matching commit is
  absent from unscanned history.
- Timed-out Git processes and their process groups are terminated after a bounded grace period on
  supported platforms, without signaling unrelated processes.
- Existing multi-repository, cancellation, error-modal, Git safety, and webview protocol contracts
  continue to pass.

## Risks

- Overly strict Flow configuration limits could reject legitimate repositories; limits need fixtures
  near both sides of each boundary and a clear diagnostic.
- Regex hardening can change accepted syntax; retain a deliberately documented compatibility subset
  and avoid silent pattern reinterpretation.
- Filesystem race mitigation differs by platform and filesystem; verify Windows and Unix behavior
  through the existing platform harness where direct atomic guarantees differ.
- Compare Results sequencing mistakes can suppress a valid update or dispose the wrong panel.
- Diff batching can change ordering, binary-file presentation, or unusual-path handling.
- Process escalation can target the wrong PID if identity and lifecycle checks are not preserved.

## Test Plan

- Add focused config fixtures for oversized files, deeply nested JSON, oversized collections and
  strings, invalid regex, and pathological regex candidates.
- Add deterministic config-persistence race coverage using target substitution at the write boundary.
- Add deferred-promise orchestration tests that complete Compare Results requests out of order and
  switch repositories between completions.
- Add large untracked-set and bounded-output unified-diff tests, retaining spaces, Unicode, leading
  dashes, binary files, and stale-path coverage.
- Add Show Log histories with a matching commit beyond the scan ceiling and assert truthful
  continuation/truncation presentation.
- Extend Git execution tests with a process that ignores `SIGTERM`, then verify bounded escalation
  and descendant cleanup on supported Unix platforms.
- Run `npm run build`, `npm test`, and the proportional platform/E2E commands recorded in the release
  artifact.

## Manual Validation

- Open a repository with a valid Flow config and confirm existing branch classification and
  governance actions are unchanged.
- Open malformed and over-limit configs and confirm an actionable error appears without extension
  host stalls.
- Rapidly switch repositories and comparisons; confirm the panel never regresses to older content.
- Generate a worktree comparison with a large untracked set and confirm progress, cancellation,
  ordering, and responsiveness.
- Search a history with more commits than the scan ceiling and confirm the incomplete scope is
  visible.
- Exercise the applicable rows in `project-context/3.deliver/extension-host-smoke-matrix.md`.

## Release-note Impact
