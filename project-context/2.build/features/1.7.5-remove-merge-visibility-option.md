# 1.7.5 — Remove Merge Visibility Option

Status: Implemented; automated verification passed.
Approved: 2026-10-17, “Siga em frente com a recomendação.”
Decision source: [necessity review](../merge-commits-visibility-review-2026-10-17.md).

## Define

Remove Show Merge Commits and its internal boolean end to end. Keep one compact
automatic projection equivalent to the previous default: preserve visible refs,
forks, roots, unreferenced tips and compressed ancestry paths in the loaded graph.
Merge commits that meet these rules remain available. No replacement switch or
new setting; merge/abort actions, Show Log, compare, focus and bisect remain intact.

Acceptance: the menu/runtime/typed protocol/defaults no longer carry this option;
old payload fields cannot re-enable it; the other View options still work.
Projection and count invariants, referenced/structural merges and compressed paths
remain tested with synthetic and real-Git fixtures. Run full build/tests, quality,
benchmark and actual Extension Host minimum/stable verification.

No new Git loading policy, fidelity promise, dependency, version, packaging or
publication. The earlier data-acquisition findings remain separate; removing a
switch does not reconstruct history omitted by Git simplification.

## Build

Removed the shell checkbox, DOM registry entry, event/loading handlers, state
synchronization, toolbar busy handling and View tooltip summary. The option is
absent from model/protocol types, validation whitelist and host/browser defaults.
No occurrences remain in production `src/` or benchmark scripts. Legacy payload
keys are ignored using the existing sanitizer; valid options in the same payload
still work. No data migration or new compatibility flag is required.

Visibility now uses references/forks/roots/unreferenced tips directly. The previous
default `false` already selected exactly this rule. Hidden commits retain their
loaded ancestry in `edge.through`; merges with visible references or structural
fork roles stay visible. Git query construction, history limits, cache policy,
merge mutation workflows and Show Log were not changed.

Runtime owners: `revisionGraphWebview.ts`, `revisionGraphTypes.ts`, projection,
model/protocol, option validation, webview DOM/toolbar modules, bootstrap and
interactions. Updated existing routing/host-state fixtures and benchmark options.
Tests that requested extra merge cards now check the compact policy, referenced
merges and exact compressed paths; no test function was deleted or skipped.

Quality ceilings tightened: bootstrap 1,732 → 1,723 lines and interactions
892 → 890. Removing one event callback shifted the unchanged complexity-22
callback from ordinal 35 to 34; only its baseline key moved. No limit increased.
