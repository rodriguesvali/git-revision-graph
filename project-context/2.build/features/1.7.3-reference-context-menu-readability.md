# Reference Context Menu Readability — 1.7.3

Status: Implemented; automated and Chromium verification passed; integrated manual smoke completed by maintainer confirmation
Date: 2026-10-03

## Problem and Verified Baseline Evidence

Users cannot identify full long reference names before choosing graph context-menu
actions, particularly checkout and deletion, in split-editor layouts.

- `src/revisionGraph/webview/styles.ts:446`: top-level menu width is fixed at 250px.
  Items hide overflow, use ellipsis and prohibit wrapping; submenus use 220px.
- `src/revisionGraph/webview/runtime/contextMenu.ts`: checkout/deletion labels contain
  the clicked reference; Merge Into contains the current branch destination, which
  may differ from that reference.
- `src/revisionGraph/webview/script/interactions.ts`: placement measures actual DOM
  bounds and maintains an 8px viewport margin; buttons receive the full label text.
- Menus already limit height, scroll vertically and constrain width to the viewport.
  `script/bootstrap.ts` closes menus on viewport scrolling and window resizing.
- The supplied screenshot demonstrates a narrow graph beside another editor pane.
  It does not establish how a specific long-name case renders.

## Implemented Direction

The maintainer authorized implementation on 2026-10-03. Both menus now size to their
content with a 480px upper bound, limited to the webview width minus 16px. The main
menu retains a 250px minimum and submenus a 220px minimum when space permits;
smaller panes shrink below those sizes. These bounds were verified in Chromium.

Keep short action/name pairs on one line. When a long reference cannot fit, keep
the action readily recognizable and let the full name continue on subsequent
lines, preferably breaking at `/` and `-`, with a fallback for unbroken segments.
Do not clamp line count or introduce horizontal scrolling. Retain vertical menu
scrolling, measured placement, keyboard access, submenu behavior and Git guards.
Keep action destinations explicit, including Merge Into when its destination is
different from the clicked reference. Hover information may supplement visibility.

This implementation follows the content-reflow principle documented by
[W3C](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html); no accessibility
conformance certification is claimed.

## Alternatives and Supporting Assessment

- Wider menu alone: improves medium-length names but still clips long names in narrow panes.
- Tooltip alone: requires extra discovery/hover and leaves the action target clipped.
- A full-name header with all target names removed from actions: reduces repetition
  but can hide distinct destinations, particularly Merge Into. A broader redesign
  would need to preserve those distinctions.

Following the typesafe-ai skill and live Choice documentation, `jev_decide`
selected bounded width plus wrapping with probability 0.98 and confidence 0.97
over these alternatives. This is supporting assessment, not a usability test or
proof. Some auxiliary requirement verdicts contradicted inspected facts (the
existing fixed-width menu already has a viewport cap); those verdicts were discarded.
The recommendation rests on source inspection and the user's reported problem.
