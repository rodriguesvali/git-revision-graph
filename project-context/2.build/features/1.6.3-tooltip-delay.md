# 1.6.3 Tooltip Activation Delay

Status: Implemented; automated validation complete; manual validation pending
Last updated: 2026-08-01
Baseline: `1.6.3` release cycle

## Goal

Prevent extension-controlled detail tooltips from obstructing context-menu access by applying a
consistent 500 ms activation delay and cancelling pending activation when the interaction moves
away or opens a menu.

## User Workflow

1. Hover or keyboard-focus a reference card in the Revision Graph, or hover a commit row in Show
   Log.
2. Keep the pointer or focus on the target for 500 ms to open its detail tooltip.
3. Leave the target before 500 ms or open its context menu to cancel the tooltip.

## Scope

- Add a 500 ms activation scheduler to Revision Graph reference tooltips.
- Retain and name the existing 500 ms Show Log commit-tooltip delay as the same product standard.
- Cancel pending or visible custom tooltips before graph, commit, or file context menus open.
- Apply the delay to both pointer hover and keyboard focus for Revision Graph references.

## Non-goals

- Do not replace native Chromium tooltips produced by HTML `title` attributes; their activation
  timing is controlled by the webview browser engine.
- Do not add a setting, command, dependency, protocol message, or Marketplace contribution point.
- Do not change the existing 180 ms Revision Graph or 160 ms Show Log dismissal grace periods.

## Touched Surfaces

- Revision Graph reference-tooltip scheduling and context-menu interaction.
- Show Log commit-tooltip constant and context-menu interaction.
- Webview contract tests, changelog, feature index, and release readiness.

## Acceptance Criteria

- Revision Graph reference tooltips do not open before 500 ms of continuous hover or focus.
- Leaving a reference before the delay expires cancels the pending tooltip.
- Opening a Revision Graph or Show Log context menu cancels and hides the relevant custom tooltip.
- Show Log commit tooltips continue to use a 500 ms activation delay.
- Native `title` behavior remains unchanged and accessible labels remain intact.

## Risks

- Delayed keyboard presentation may require users to pause briefly before tabbing into tooltip
  actions.
- A stale timer could reopen a tooltip over a context menu unless every hide path cancels both show
  and hide timers; focused source assertions cover these cancellation boundaries.

## Test Plan

- Assert the shared 500 ms constants and delayed scheduling in both generated webview runtimes.
- Assert pointer and focus routes use the Revision Graph scheduler.
- Assert hide and context-menu routes cancel pending tooltip activation.
- Run `npm run quality:check`, `npm run build`, `npm test`, `git diff --check`, and
  `graphify update .`.

## Manual Validation

- In an Extension Development Host, hover each Revision Graph reference kind for less than and
  longer than 500 ms; verify short transits do not open a tooltip.
- Right-click a reference before and after the tooltip opens; verify the context menu is unobstructed
  and the tooltip does not reopen while the menu remains open.
- Repeat the hover and context-menu checks for Show Log commit and file rows.
- Keyboard-focus a graph reference, wait for the tooltip, move focus into its actions, and verify
  Escape and focus-out dismissal remain usable.

`1.6.3` Revision Graph notes.
