# Flow Governance operation preview — 1.7.1

Status: implemented; automated verification passed; manual smoke pending
Date: 2026-09-05

## Define

Fourth maintainer-authorized incremental improvement: show source, target/base, expected branch name
and operation effects before submitting branch-start or equalization forms. Use the repository's
configured naming rules from the host, including custom prefixes and canonicalization.
Acceptance: branch creation explains checkout and the later publication offer; equalization explains
creation from the target and merging the origin into the new local branch, without automatic push.
A preview never fetches, mutates, checks out, pushes, or reserves a name. Actual submission retains all
existing readiness, collision, configuration and mutation guards.

## Build

- `flowFormPreview.ts` reuses the branch and equalization name resolvers and Git name validation.
  Missing/invalid names produce an unavailable preview with context rather than an invented name.
- Add bounded, repository-scoped `preview-flow-form` requests and correlated `flow-form-preview`
  responses through validation, authorization, dispatch rejection feedback, handlers, host factories,
  trace passthrough and browser guards. Preview requests omit the description entirely.
- `formWorkflow.ts` resolves configuration read-only and drops completions after repository switch
  or disposal. Browser preview controllers debounce edits by 150 ms, reuse unchanged requests,
  cancel scheduled work on close and ignore responses for older edits or other repositories.
- Both dialogs display host text in a live status region using textContent. Structured branch IDs
  and short names are combined as for submission. Equalization updates when its origin changes.
- Preview text is bounded visually with scrolling and wrapping; the dialog itself scrolls in short
  viewports to keep the submit/cancel actions reachable. Preview readiness is advisory: collision
  checking still occurs during submission.
