# Show Log Expanded Change Search — 1.7.4

Status: Implemented; automated verification passed; focused Extension Host smoke pending
Date: 2026-10-09

## Scope and Acceptance Criteria

The maintainer requested `change:` search in expanded commit files and automatic
propagation of the active commit-level change search. Extend the existing file
filter, preserving case-insensitive path/status text. Advanced `change:` values
remain literal and case-sensitive in added/removed lines, with quoted values.
When a global change query also has `file:`, inherit both operators so the expanded
list identifies the same changed path; omit commit metadata text. Users can edit
or clear the inherited filter. Reset filters across source/repository/global-query
changes and retain explicit edits, including clears, when reopening a commit.

Use one bounded native Git query per selected commit/filter, returning matching
paths, with cancellation, debounce and stale guards. Keep the complete cached
change list and original action IDs. Loading/errors must not claim no matches.
Cover roots, first-parent merges, deletions, rename paths, literal punctuation,
unusual filenames, large file lists and malformed filters. No dependencies,
contributions, persistence schema, Git mutations or deployment changes.

## Design Evidence

Graphify located the existing commit query and expanded-file UI. Inspection confirms
the current file filter searches path/status only. Existing commit search uses
escaped Git `-G`; expanded files compare against the first parent.

Jev `jev_decide` selected one native matching-path query over per-file patch loads
or full-patch parsing (probability 1.0, three requirement checks supported). This
is an assessment, not correctness proof; verified with real Git fixtures. Context7's
first query returned no matching docs; a refined query retrieved the `-G` semantics
but incomplete path-output coverage. Official [Git 2.25 log docs](https://git-scm.com/docs/git-log/2.25.0)
describe `-G`, `--name-only`, `-z` and `--pickaxe-all`. Exact old-version runtime compatibility
remains distinct from documentation evidence.

## Implementation and Review

- Reuse the existing native query builder with an empty commit format and
  NUL-delimited names instead of hashes, without `--pickaxe-all`. First-parent,
  root, literal path/text, disabled external diff/textconv and execution bounds
  match the commit query. One process returns paths; no full patch is transferred.
- The file-search workflow owns bounded per-commit overrides, including explicit
  clears, scoped requests and original change IDs. Only active loaded expansions
  accept the validated `setCommitFileFilter` message. Source/filter changes reset
  the overrides and abort pending searches.
- Extract commit expansion and file-search browser rendering from the provider
  and HTML shell. Preserve full cached changes and all file actions. Reduce the
  existing file-size/validation-complexity baselines; no quality limits increased.
- Browser input uses a 200 ms debounce, preserves cursor/focus and displays
  distinct loading/error/no-match feedback. Flush a pending edit before collapse
  or commit switch; a browser regression reproduced the lost-draft race before
  the fix, and the same scenario passed afterward.
- Existing browser-only hash-keyed persisted file filters are no longer used as
  query state; session overrides are host-owned and reset with source/global scope.
  Graph width and commit selection persistence are preserved.
