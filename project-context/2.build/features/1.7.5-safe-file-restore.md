## Scope and Acceptance Criteria

Correct the shared file-restore executor used by Compare Results and Show Log:

- Resolve a selected reference to one commit for the entire operation.
- Validate all source paths, mappings, destinations and existing path guards before
  the first worktree mutation. Invalid later actions must leave earlier files intact.
- Back up affected worktree entries before mutation and recover their previous
  bytes, executable modes, symlinks and absence after a runtime failure.
- Preserve recovery copies and report their location if recovery itself fails.
- Retain Git restore semantics, staged/index contents, user confirmation and
  per-repository mutation coordination. No changes to the other review findings.

## Implementation and Verification Plan

1. Reproduce invalid later sources/mappings with failing real-Git tests; add full
   preflight and pin the resolved commit.
2. Add failure-injection regressions and bounded per-operation recovery copies;
   verify partial writes/deletions and recovery failures.
3. Verify shared presenter error handling, existing semantics and path guards;
   run build/full tests, quality, platform checks and graphify update.

Use existing Node filesystem and Git execution facilities without dependencies.
Backups are private temporary operation data, removed after success or successful
recovery. They remain available only when recovery needs manual intervention.
This provides exception recovery, not atomicity against process termination or
uncoordinated external writers.

## Implementation

- `src/compareResultRestoreExecutor.ts`: resolve the ref once; inspect exact paths
  with literal `ls-tree` (only blob sources); preflight the whole plan; back up all
  targets before attempting writes; recover attempted targets on failure. Literal
  restore pathspecs prevent a selected `[ab].txt` from also overwriting `a.txt`.
  Git inspection failures propagate instead of being mistaken for absent sources.
- `src/compareResultRestoreBackup.ts`: focused filesystem boundary with per-operation
  temporary copies and a target-to-copy manifest. Capture regular files, links and
  absent targets; reject directories/special files. Recover attempted entries in
  reverse order and recheck ancestors before recovery. Never follow destination
  links when recreating regular files; retain the manifest/copies if any recovery
  fails. Existing ancestor validation moved here with an executor re-export.
- `test/compareResultRestoreExecutor.test.ts`: real-Git and injected-process-failure
  regressions, including both actual host workflows through their existing service
  boundaries. No new production test hooks or dependency injection were needed.
- README, CHANGELOG, SAD, active feature/cycle records, review follow-up, release
  readiness and smoke matrix describe the approved correction and remaining gates.

## Limits and Manual Follow-up

Run the focused [Extension Host matrix](../../3.deliver/extension-host-smoke-matrix.md)
before release acceptance. Real modal/panel transport and Windows/macOS execution
were not verified in this environment. File-symlink tests are platform-gated on
Windows because creating them requires privileges; the Linux run skipped none.

Temporary copies bound memory use, but add disk I/O proportional to the selected
files (normal plans contain at most two targets). Recovery covers exceptions,
including partial CLI writes, not process crashes or arbitrary external writers.
It restores file bytes/modes, symlink targets and absent files, not every filesystem
attribute or hard-link identity. Failed temporary cleanup is logged with its path;
an incomplete recovery reports retained copies through the existing modal error
presenter. No packaging, installation, tagging or publication was performed.
